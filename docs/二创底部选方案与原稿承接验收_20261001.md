# 二创底部选方案与原稿承接

## 用户流程

读完二创结果，在底部选择方案 1、方案 2……或全部方案，再选择审稿优化、分镜脚本、生成选题、脚本生成、标题封面、开篇钩子、自由对话。方案正文保持原有排版，去向按钮统一尺寸并按网格排列。

每次跳转携带当前正文和原始方案。原始方案用于保留创意、背景和约束，最新正文用于本轮操作。相同正文只在模型提示中发送一次；后续版本的原始方案随生成历史保存。读取历史时按当前结果匹配来源，避免夹带另一份正在编辑的稿。

## 实际验证

生产网站使用「锦园地摊串串一元火锅」档案的五方案历史，选择方案 3 分别跳转七个板块。七个目标都收到所选方案的内容，未夹带其他方案；七个板块都实际提交并生成了结果。

| 板块 | 实际承接 |
| --- | --- |
| 审稿优化 | 口播进入待审稿框，完整方案作参考；未选维度也能全面审稿 |
| 分镜脚本 | 口播进入脚本框，完整方案作拍摄参考 |
| 生成选题 | 完整方案进入创作参考，实际生成五条选题 |
| 脚本生成 | 主题和完整方案进入补充说明，实际生成脚本 |
| 标题封面 | 完整方案进入脚本参考，实际生成三条标题 |
| 开篇钩子 | 从口播提取开头，完整方案作参考，实际生成六个开篇 |
| 自由对话 | 完整方案进入可编辑草稿，发送后生成回答并同步云端 |

审稿、分镜、选题、脚本、标题、开篇、自由对话的结果均重新加载验证。开篇初次未恢复，查明恢复逻辑在档案就绪前退出但没有重试，修复后已恢复六张开篇卡，正文与刷新前一致。

「全部方案 → 审稿优化」带入 14234 字，保留方案 1 至方案 5，未只取第一段口播。「审稿结果 → 分镜脚本」带入优化后的正文，审稿意见作为参考。「标题结果 → 脚本生成」实际补充说明 3912 字，同时包含原始方案 3 和当前标题版本。

## 修复和约束

- 新内容进入目标页时，不回填其他历史结果或用作品旧稿覆盖新稿。
- 审稿保留主题、事实和叙事关系；分镜承接当前台词；选题围绕原方案延伸；脚本保留原创意；标题和开篇只承诺正文能兑现的内容。
- 既有 AI 稿、拍摄设想、例子不是已核实事实。X 串、XX 元和待核实信息不得补成真实数字；与档案冲突时标注待核实。
- 实测发现旧标题生成把 X 串补成 20 串，已加强各板块的承接和事实约束。历史旧稿保留，未删除。功能流转通过不代表 AI 文案的全部经营事实已人工核实。
- 加强约束后的三标题复测没有再补写 20 串，新标题刷新后正文一致。已有 AI 稿中的其他经营事实仍需按实际情况核实，不能把一次模型生成的结果当作事实证明。
