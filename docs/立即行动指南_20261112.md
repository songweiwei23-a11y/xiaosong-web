## ⚡ 第 3 步：优化数据库索引（1 小时）

### 问题说明
3 个高频查询表缺少关键索引，导致：
- 用户查看历史记录变慢
- 管理员审核订单变慢
- 当数据量超过 10 万行时，页面可能卡顿

### 立即执行

#### 3.1 打开 Supabase SQL Editor

访问: https://supabase.com/dashboard/project/你的项目ID/sql

#### 3.2 执行以下 SQL（逐条复制执行）

**索引 1: 脚本历史查询优化**
```sql
-- 用户查看自己的脚本历史时加速
CREATE INDEX CONCURRENTLY idx_script_history_user_time 
  ON script_history(user_id, created_at DESC);
```

**索引 2: 创作完成证据查询优化**
```sql
-- 额度结算时查询加速
CREATE INDEX CONCURRENTLY idx_creation_evidence_user 
  ON creation_completion_evidence(user_id, created_at DESC);
```

**索引 3: 订单审核列表优化**
```sql
-- 管理员"待审核订单"页面加速
CREATE INDEX CONCURRENTLY idx_payment_orders_review_list 
  ON payment_orders(status, created_at DESC);
```

#### 3.3 验证索引创建成功

```sql
-- 查看所有索引
SELECT 
  schemaname,
  tablename,
  indexname,
  indexdef
FROM pg_indexes
WHERE indexname LIKE 'idx_%'
ORDER BY tablename, indexname;
```

应该看到刚才创建的 3 个索引。

### 为什么使用 CONCURRENTLY

- ✅ **不锁表**: 创建索引期间用户可以正常使用
- ✅ **生产安全**: 不会影响正在运行的查询
- ⚠️ **稍慢**: 比普通索引慢 2-3 倍，但更安全

### 本周内（2-3 天）

#### 1. 为 API 添加超时设置

**为什么**: 70% 的 API 没有超时，可能导致连接挂起

**怎么做**: 在每个 `app/api/**/route.ts` 文件顶部添加：

```typescript
// 根据实际情况设置
export const maxDuration = 30; // 秒
```

**推荐值**:
- 简单查询: 5-10 秒
- AI 生成: 30-60 秒
- 批量操作: 60-120 秒

**快速查找缺少超时的 API**:
```bash
# 查找所有没有 maxDuration 的 route.ts
Get-ChildItem -Path "app/api" -Recurse -Filter "route.ts" | ForEach-Object {
  $content = Get-Content $_.FullName -Raw
  if ($content -notmatch "maxDuration") {
    Write-Host $_.FullName
  }
}
```

## 🚑 如果遇到问题

### 问题 1: npm audit fix 失败

**症状**: 提示无法自动修复

**解决**:
```bash
# 强制更新（可能有破坏性变更）
npm audit fix --force

# 或手动更新
npm install next@latest eslint-config-next@latest
```

### 问题 2: 推送到 GitHub 冲突

**症状**: `git push` 提示 rejected

**解决**:
```bash
# 拉取远程变更并变基
git pull --rebase origin main

# 如果有冲突，解决后继续
git add .
git rebase --continue

# 推送
git push origin main
```

### 问题 3: 数据库索引创建失败

**症状**: SQL 执行报错

**可能原因**:
1. 表不存在 - 检查表名拼写
2. 索引已存在 - 先删除旧索引
3. 权限不足 - 用管理员账号登录 Supabase

**解决**:
```sql
-- 检查表是否存在
SELECT * FROM information_schema.tables 
WHERE table_name = 'script_history';

-- 如果索引已存在，先删除
DROP INDEX IF EXISTS idx_script_history_user_time;

-- 再重新创建
CREATE INDEX CONCURRENTLY idx_script_history_user_time 
  ON script_history(user_id, created_at DESC);
```
