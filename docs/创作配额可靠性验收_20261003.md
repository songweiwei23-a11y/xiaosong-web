# 创作配额可靠性

## 本次改动

- 所有实际扣费生成入口统一预占：`dify/stream`、`dify/chat`、`interview/extract`。上传、转写只做额度预检查，不扣创作次数。
- 订阅/额度读取异常、记录创建异常一律返回可重试 503；缺失预占迁移不会回退旧计数。
- 同一用户通过 PostgreSQL 事务锁串行预占；已用次数加未过期预占共同参与限额判断。
- 成功后在一个事务内增加计数、写使用事件、确认请求；失败释放，重复确认不会重复计次。
- `X-Generation-Id` 是客户端单次生成编号，网络重试保持不变。未传的旧客户端由服务端分配并从响应头返回。相同 ID 不再启动模型，返回 409；同 ID 不同内容也拒绝。
- 显式上游错误、空回答、缺少完成标记不算成功；自由对话客户端断开后继续读取上游，避免完整产出被误释放。
- 会员周期换期在事务内执行；旧周期晚到结果只记使用事件，不占新周期次数。免费体验及会员过期规则保持原配置。
- 撤销普通登录用户直接写额度表的权限，保留已有读取能力。联网搜索独立额度及 RPC 未更改。

## 发布顺序

1. 执行 `supabase/migrations/20261003_creation_quota_reservations.sql`，不会清空现有额度或删除业务数据。
2. 使用 `supabase/tests/creation_quota_preflight.sql` 检查 RPC、权限、RLS；普通用户不能修改余额或调用额度 RPC。
3. 发布生成路由及客户端请求编号后，使用受控测试账号验收并发最后一次额度、重复编号、失败释放及成功确认。

## 本地验证

- 相关 8 个测试文件共 231 项通过，包含守卫数据库异常、预占失败不请求模型、HTTP 失败释放、部分回答后报错、缺少结束标记不计费、客户端关页后仍准确确认。
- 类型检查通过。
- `scripts/verify-creation-quota.cjs` 在隔离 PGlite PostgreSQL 实际执行完整迁移两次并运行 12 项 SQL 场景：超额预占、重复编号/冲突、双确认、释放、功能独立、崩溃预占到期、换期、会员过期、封禁、事务回滚、总量池及 RPC 权限。
- 临时测试运行库安装在 `.tmp/quota-probe`，没有加入项目依赖或锁文件；复跑前安装 `@electric-sql/pglite@0.3.14` 到该目录。
- 未执行线上付费模型调用、未部署、未改生产账号额度。PGlite 在一条连接上排队处理并发请求，不能替代真实多连接 PostgreSQL 压力验收。

## 已知边界

- 进程崩溃后未知预占保留两小时，之后不阻挡新请求；正常生成失败立即释放。
- 成功确认的网络错误按同 ID 重试三次，仍失败时保留预占并提示同步延迟，不能释放已成功生成的请求。持久数据库故障下仍需要后续结合已存作品/生成 ID 的后台对账，避免两小时后过期造成少计。
- HTTP 连接丢失且无法取回结果时不向用户扣成功次数，但上游模型可能已发生费用。应在成本监控中统计此类失败，不能假设所有失败完全无 API 成本。
- 旧客户端未主动复用生成 ID 时无法识别其重新提交；新客户端应统一通过生成请求封装设置该头。
