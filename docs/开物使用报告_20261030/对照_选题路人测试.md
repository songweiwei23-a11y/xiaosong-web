# 新旧对照：选题（judge-ab-topic）

2026-11-01。12 个测评档案，每份 6 条选题里抽第 1、第 4 条；旧版、新版在同一时段交替生成、交替评审，评估器不知道哪份是新版。T1 路人听得懂、T2 爆款元素（按目的）、T3 只有这家拍得出来、T4 拍得出来（不靠编）。

**试的改法**（`lib/tool-first-1021.ts` 的爆款元素要求，换掉两句、不加条数）：
- 旧：「每条选题必须落在上面某一个句式上，把 X 换成本行业的具体东西」「句式是知识库给定的，不要自己另造一套」
- 新：「每条选题用上一个元素，标题里看得出来；句式可以照套，也可以不套、只要看点是这个元素」「标题念给不在这个行业的路人听，要一听就懂、觉得跟自己有关；要先懂行里的工序、行话才看得懂的切口，换成路人身边的事来说」

**结论：不上线，已撤回。**
- 路人听得懂（T1）新旧一样，都是 21 / 24；整体新版 17 / 24，反而比旧版 19 / 24 低。
- 新版多出两条编的东西：「十个妈妈里有七八个都是临时跑来买这个」「有次去看老房，业主说想把厨房和客厅打通……」——「换成路人身边的事」把模型推去编生活场景。
- **更重要的发现**：输入改对以后（第一行是「生成6条选题（…按配比搭配）」，不是写死的「生成6条流量型」），现行线上版本本身就有 19 / 24 合格，72 条标题里带「第一次」的 3 条、带「外行人绝对不知道」的 0 条；基线里是 138 条里 45 条、18 条。产品方判「切口太专业」的那批选题，是在错误输入下生成的。
- 还剩的毛病（新旧都有）：标题卖关子说不清（「我会先确认这个」「其实我每天做得最多的是这件事」）；人设型选题的核心动作留成【换成你的真实…】占位。
