## 一、这次测了什么，没测什么

**测了**：19 个生成节点 × 3 个行业，共 57 次真实模型调用，全部成功（0 失败）。节点之间按链路串联：账号定位 → 商业定位、内容定位 → 创作简报、行业建议、起号方案 → 内容规划 → 创作方向 → 选题 → 脚本 → 分镜、标题、开篇、审稿 → 二创、拆解、成交理由、对标、前采提取。

三个行业（虚构材料，不是真实客户）：
- **A 川味餐饮**（地摊串串，出镜人是成都来的川菜厨师，本人掌勺）
- **B 大码女装**（店主本人出镜）
- **C 本地家具店**（老板本人出镜）

**没测**：
- 自由对话、开物助理、知识库查询（需要会话或检索服务，不是单次生成）
- 素材库、作品、会员、后台等纯数据页面（没有模型生成）
- 每个节点的所有模式变体（例如脚本的 7 种四大脚本、37 种 36 计，成交理由的 17 条逐条）。每个节点只测了默认模式一次。

**局限**：
- 测评直接调用提示词构造函数和模型，不经过线上页面、额度、门禁，也不包括编造细节检查、说话人修正、事实修正这些后处理。
- 每个节点每个行业只采样一次，结论是「这一次的表现」，不是稳定率。
- 人工细读的范围有限：脚本（10，A 和 C）、开篇（13，A）、选题（09，B）已细读；其余节点只做了机械检查，没有逐条细读。下面的评分中，标「待核」的就是没有细读的。

## 四、主要问题（按严重程度）

1. **配比数字编造**（01、03，以及 A/05、C/06 的少量数字）。模型在提示词没有给出配比的情况下，自己编了百分比，并且以事实的口吻写进定位。这是事实问题，可能误导编导。
2. **脚本占位太多，可用性低**（10，A）。台词里大量「【待确认】」，观众拿到的是一个框架，不是能拍的脚本。
3. **36 计与四大脚本叠加**（10，A 和 C）。脚本写成「对比型公式 + 36 计·第 X 计」，没有统一到一棵脚本树下。这和用户的定义冲突，也是另一个会话正在改的问题。
4. **统计口径错误**（18）。一条样本算「占 100%」，表述上像是统计结论。
5. ~~**规则泄漏**（11，A）~~ **已更正**：原文记为分镜里漏出「不念师傅、主厨」，核对 `runs-r5` 输出后没有这一处。误判来源是把提示词里的规则原文当成了输出。见 `03-整改记录.md`。
6. **输出过长**（06、16）。起号方案和拆解爆款的输出长度远超一般使用需要，编导阅读成本高。
