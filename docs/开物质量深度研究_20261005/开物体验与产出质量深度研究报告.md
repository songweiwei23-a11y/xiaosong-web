# 开物体验与产出质量深度研究报告

评估日期：2026年10月5日。对象：开物当前代码、现有正式服务器、正式Dify API、最近一次本地工作流导出及此前验收记录。

本报告是一次带真实模型调用的工程与内容质量审计。没有修改业务代码、Dify参数、数据库结构、会员价格或生产部署。新建了专用Dify评估会话和本地证据文件，没有把测试稿写入网站客户历史、会员配额或作品数据。

## 1. 先回答：现在是什么水准？

**开物已经是具有业务价值的短视频编导辅助工作台，能够较快产出结构完整、贴近经营场景的可编辑初稿；目前还没有达到“自动交付、无需核对”的专业内容生产系统水准。**

它的强项是把档案、视频目的、脚本公式、拍摄条件、历史和继续创作集中到一个流程中。弱项是事实约束仍会失守、联网来源判断不稳、规则评分与实际稿件质量不一致，以及所有任务共用偏重的检索和提示词。

“可以收费提供辅助服务”和“可以保证生成的稿直接发布”是两个不同的结论。前者有现实基础，后者目前没有证据支持。没有做竞品同题盲测、专业编导双人评分或真实发布效果实验，因此不称它为行业前几名、不标客观的8.8分或9.5分，也不声称已达到Claude官网的综合水准。

采用四个使用层级描述，避免制造精确分数：

1. **草稿工具**：能给思路，关键事实和可执行性依赖人工重做。
2. **专业辅助**：能交较完整初稿，用户编辑和核对后使用。
3. **受控交付**：在明确范围内，事实、来源、结构、时长经过可靠验证后交稿。
4. **自动交付**：广泛场景下很少需要人工介入，且有持续业务数据证明。

开物综合更接近第二层；单次资料提取和局部改写在此次样题里表现良好，联网事实核查与未经提供的人物故事仍可能降到第一层。这个分层是本次审计的产品判断，不是行业排行榜。

## 2. 研究方法及证据边界

### 本次实际做了什么

- 核对生产构建：`FKKyHb_kTqwkQYiyrnUlu`。五个关键文件与本地SHA-256一致：质检、档案上下文、创作承接、偏好学习、发布反馈。
- 正式服务器进程在线，内部登录页面HTTP 200。内部一次请求约2.4毫秒，**不能代表用户网络、登录、数据库或模型的总耗时**。
- 从正式Dify API读取已发布附件参数，确认图片和文档开启、最大数量6。
- 运行13次正式Dify API样题：9次受控探针，包含一次同题重复、一次脚本到分镜连续传递；另4次直接使用项目原生提示词构建器。
- 另做一次真实研究分节：现有服务器密钥→阿里云搜索→读取前两个网页→项目研究提示词→正式模型。
- 对事实和禁忌规则做离线复现，并人工阅读所有生成结果。原生审稿质检对完整回答直接调用规则；评估脚本最初重复截取正文的错误已在分析记录中纠正，没有把该评估器错误写成产品缺陷。
- 查阅Dify、Anthropic官方文档，用于核对记忆、检索、参数及评测方法。

### 本次不能证明什么

样本主要覆盖本地柜业、餐饮、美甲和两个一般问答任务，且有意设置了事实冲突，属于小样本诊断，不是随机生产质量调查。每题大多只跑一次，未测试多日、多网络、多用户或大并发。

审计者参与过项目实现，人工评价也由同一审计者完成，存在熟悉系统造成的判断偏差。本报告公开输入、原回答和规则结果供复核，但不能替代独立专业编导的双人盲评。

调用从现有服务器发出、同批最多两题并行、均为新会话，不带真实客户资料；没有经过浏览器所有表单、会员拦截及历史保存。因此时间属于**服务器到Dify的此次样本**，不能作为正式SLA；内容结论也不能直接推成全部行业的错误率。

当前连接的浏览器未登录Dify及开物，已尝试打开正式页面；没有获得新的已登录界面验收。Dify控制台完整已发布节点参数尚未重新导出：模型名和提供商由本次运行事件确认，温度等详细参数依据本地2026-10-02导出，需区分这两类证据。过去2457项测试的通过记录是2026-10-04的验收结果，本次没有把它冒充当前版本重新跑过的结果，更没有用测试数量推断内容质量。

## 3. 正式模型和Dify参数的判断

| 配置 | 核对到的值 | 证据及影响 |
|---|---|---|
| 主模型 | `claude-sonnet-4-6` | 13次运行事件一致；是接口声明的模型标识，不能独立鉴定转接供应商的实际底层实现 |
| 模型提供商 | `openai_api_compatible` | Dify兼容接口插件，不能据此称Anthropic官方直连 |
| temperature | 0.5 | 本地DSL；通用折中值，尚无按任务A/B验证 |
| top_p | 0.9 | 本地DSL；未获取转接方最终接收/改写参数的证据 |
| max_tokens | 50000 | 本地DSL的输出上限；不是每次消耗量，也不会自动让稿件更专业 |
| 会话记忆 | window开启，size=20 | 本地DSL；不是永久全量记忆，也没有在本轮做超过窗口的连续对话实验 |
| 图像 | enabled，detail=high | 本地DSL；利于细节识别，代价是较高输入负担，本轮未新增困难图片准确率测试 |
| 上传 | 图片+文档，最多6个 | 本次正式API参数；不等于任意格式、任意扫描质量都能正确识别 |
| 知识检索 | 五个固定检索节点，各返回4条 | 本轮运行实测；每题20条片段，普通Excel题也执行全部节点 |
| Rerank | BAAI/bge-reranker-v2-m3 | 本地DSL；配置为reranking_model模式 |
| 相似度阈值 | null | 本地DSL；缺少节点级最低相关性门槛，实际也返回了不相关题目的片段 |
| 向量/关键词权重 | 配置内有0.7/0.3 | 但当前选的是模型重排模式，不能把保留的weights对象当成“该权重已实际参与每次计算”的证明 |
| LLM context | enabled=false，提示词直接插入五组结果 | 不能据此说知识库没有生效；检索结果确实进入提示词，但需要另做来源映射，不能假定原生引用自动可靠 |

本地系统提示词约8169字符，规定视频目的、公式、钩子、情绪、金句、单一行动指令，另有自由对话与附件的例外规则。这种结构明显帮助了格式完整性，但规则密度高，且模板与案例容易把“要有具体细节”推向“补一个听起来真实的故事”。

参数本身没有证明已调到最优。Dify说明温度、Top P、视觉细节、节点记忆分别控制不同能力；节点记忆不会自动跨不同conversation保留。[Dify LLM文档](https://docs.dify.ai/en/cloud/use-dify/nodes/llm)

后续应先确认接口真正支持并执行哪些参数，再做任务分组实验。可把审稿/资料提取、创意选题、脚本润色分别评测；温度0.2/0.5/0.7只是可试候选，不是已经证实的最佳值。一次只改变一个采样控制，并保留旧配置对照。输出上限也应按单条稿、长方案、研究报告分开实测，不能一刀切降到很小导致截断。

W1的答案与官方LLM文档直接冲突：节点记忆仅维持当前Chatflow会话的上下文；该文档也明确说明视觉高细节在准确度和token开销之间的取舍。搜索成功只证明拿到了结果，不证明结果足以支持答案。[Dify官方说明](https://docs.dify.ai/en/cloud/use-dify/nodes/llm)

### 深度研究分节比普通联网怎样？

本次实际确认服务器的研究密钥已经存在且能解密调用，不再沿用10月4日“未配置”的旧结论。一次搜索约0.87秒，读取两个官方域名页面，研究分节模型生成约15.14秒，均成功。

改善点：分节标注来源编号，对跨会话结论标“推断”，没找到Vision材料时承认缺失，比W1的“官方已验证”更克制。

剩余问题：搜索返回的是旧路径的“变量赋值”“工作流”等页面，未命中最直接的LLM页面；分节又把LLM历史记忆与会话变量机制混在一起。官方资料存在但没有被这一轮找到，不能把“没检索到”写成“官方没有说明”。

只测了一个分节，不是完整多问题研究、总报告综合、会员计费、任务恢复和引用一致性的端到端验收。研究功能具备真实运行基础，研究质量尚不能标为成熟。

## 5. 速度、成本与稳定性

13次API样题全部收到完整终止事件，没有超时或接口报错，这是积极证据；不是生产全量成功率100%，更不是全年可用性证明。

| 样本指标 | 最小 | 中位数 | 最大 |
|---|---:|---:|---:|
| 首个内容片段 | 5.76秒 | 7.54秒 | 14.59秒 |
| 完整生成 | 8.99秒 | 22.63秒 | 61.94秒 |
| 模型报告输入token | 27754 | 32213 | 36292 |

原生审稿完整生成约62秒、方向约59秒。用户若只看到转圈，会觉得慢；应明确显示真实阶段，并优先提供可读初稿和完成状态。以上含同批并行影响，未拆出各网络层，更没有测首屏到用户看到文字的时间。

输入负担明显偏重：Excel问答仍约28068输入token；一个只改中段、返回30字符的操作也约31477输入token。每次都检索五组知识库是实际可见的设计，检索约2-4秒，但不能在没做移除实验前断言“删掉检索就会快几倍”。

Dify运行事件里的`total_price=0`不能当作免费。兼容提供商可能没有配置成本元数据；本轮没有上游真实扣费、缓存命中和账单核对，不以该字段计算利润。

当前新浏览器访问的IP入口仍是HTTP并显示登录页。敏感账号与内容传输应优先统一HTTPS。单进程在线、有限测试通过和已有恢复设计都不等于高并发稳定；本轮没有做故障注入、负载测试或恢复演练。

| 初稿完整性 | 较好 | 台词、结构、镜头、行动入口通常完整，用户不用自己从零组织 |

| 自由度与可玩性 | 功能基础较多 | 方案选择、局部改写、锁定、版本、回退可形成玩法；还缺可靠的分支比较和约束展示 |

| 长期粘性 | 有形成资产的基础 | 档案、真实素材、已采用稿、偏好、发布反馈比单次聊天更有价值；尚未核验留存率和采用率 |
| 质量保障 | 规则辅助，不能担保 | 有成功/空稿/事实/禁忌提醒，但既会漏报也会误报；模型自检与系统规则都不等于专业审稿 |
| 稳定性 | 本次稳态调用良好 | 13次完整返回；更高负载、弱网、附件边界、故障恢复仍需专门验证 |
| 商业成熟度 | 适合受控试用和辅助服务 | 可提供真实便利，暂不适合承诺全自动正确、保证爆款或保证获客 |

设计方面沿用既有视觉，不建议为这次优化全面换风格。体验应通过减少重复输入、清楚展示承接信息和编辑保护来改善。上次评估中的“历史500条静默裁切”已在当前代码注明不再裁切存储，不把它重复列为当前确认故障；“保存历史”与“模型每轮完整记住全部历史”仍要分开。

拆解爆款采用镜头检测、关键帧拼图和文字信息辅助分析：开头加密取帧，后续选代表帧，视频和拼图有体积预算。它有真实技术实现，但不是模型逐帧看完视频，也不能从一条视频推导出确定的爆款因果。本轮没有新跑视频、声音或困难扫描件识别；不给这些维度虚构准确率。

## 7. 确认的问题与优先级

### 优先级一：影响交稿可信度

**A. 缺事实时新造案例和数字。** S2/T1/R2/N1有直接证据。事实应分“已确认、待确认、建议情境”，写入稿件前校验；用户要故事但没给素材时，提供取材问题或明确的假设示例。涉及人物评价、效果、价格、资历和服务承诺，不用技巧要求推动编造。

**B. 官方来源冒认和概念混用。** W1及研究分节有证据。官方事实问题先限定权威域名，检查问题是否与页面里的对象一致；每个结论绑定证据，不足时承认不足。再增加查询补充与阅读核对，而不是仅检查有无网址/编号。

**C. 质检“通过”与发布质量脱节。** 当前规则可复现：档案只有“从业38年”，输出“这款38元”不会被价格规则拦下；“90%的人第一步错了”也无统计来源提醒。“最大角度”“挂衣区”又触发误报。应按事实字段和正文语境核对，而不是只看数字是否在材料任意位置出现，或文字是否包含某个“区”“最”。禁忌误报是规则观察，不是法律合规结论。

**D. 分数造成虚假专业感。** 原生R2里3.5与0.5并存；现有脚本“MCN级”分数主要由格式和关键词规则产生，没有独立专家校准。建议把结构完整、事实待核、时长待测、改动范围分开显示，不用一个总分代替实际质量。

### 优先级二：改善速度、自由度与创作连续性

**E. 固定全库检索与超长通用提示词。** 建议先做按任务路由：Excel/资料计算不用编导库，分镜优先执行库，选题优先选题库，必要时补检索。检索阈值需要用正负样本调，不凭感觉随便定一个分数。[Dify检索设置](https://docs.dify.ai/en/cloud/use-dify/nodes/knowledge-retrieval)

**F. 用户短要求可能被模板压过。** `app/dashboard/script/page.tsx`按补充要求是否超过100字符决定优先级：短要求分支明确写“MCN标准 > 用户补充要求”。“只改开头，不改正文”虽然很短，约束却很重要。这是代码确认的冲突风险，不是本次已复现每次都会改错；建议事实、用户明确限制始终高于风格模板。

**G. 自动承接不等于自动选到最优。** 当前已有根稿、当前版本、目标设置和档案上下文。下一步应显示系统继承了什么：人群、目的、结构、选中方案、固定开头、不可改事实；允许用户展开调整并回退。模型输入历史有窗口和摘要：拆解/二创参考历史最多最近8条、每条1200字符，因此不能宣传成全部历史永久进入模型。

**H. 镜头时间与朗读、操作时长脱节。** B1的6-11秒镜头放了46个汉字，还要比划演示。应对台词做程序计数、允许用户选择语速和停顿、进行实际朗读或音频测时；不接受模型自称“时长合适”作为唯一验证。

## 8. 如何把它提升一个层级

先修“能否信”，再修“是否快”，最后扩展“更好玩”。以下是建议计划，没有在本轮改动正式系统。

| 阶段 | 实施内容 | 验收方式 |
|---|---|---|
| 第一阶段：1-2周 | 事实字段约束、故事素材不足处理、官方来源限制、取消误导自评分；修短要求优先级 | 此次失败样题均进入固定回归，人工确认改稿没有另造事实；新增未提供客户故事、统计比例与报价测试 |
| 第二阶段：2-4周 | 按任务检索和提示词路由；短稿/长方案参数分组；语速与镜头时间校验 | 同题旧配置/新配置比较，至少30-50个代表任务、每题多次采样；同时统计采用质量、首片段时间、总时长、token和实际费用 |
| 第三阶段：4-8周 | 以作品组织分支、承接、版本与定稿；反馈学习明确可查看/删除；建立真实素材采集入口 | 从任意阶段开始，跨至少三个板块，人群/目的/事实/开头保持；切档案不串数据，换设备能找回 |
| 第四阶段：持续运营 | 小规模真实用户试用、同题专业编导双人盲评、采用稿与发布反馈持续回归 | 区分草稿采用、重写、未采用；记录修改原因。发布效果按目的/平台/观察时长分组，不把播放量波动归功于模型 |

建议后续的核心指标：

- **事实新增错误率**：是否添加了未确认事实，不仅检查数字。
- **可拍采用率**：小改即可拍、需大改、废弃，分别记录。
- **承接保持率**：人群、目的、结构、事实和选中方案是否保留。
- **来源支持率**：链接可打开且真正支持对应结论，不把“有链接”当通过。
- **操作成本**：完成同一作品的点击、补填、等待和来回次数。
- **稳定性与费用**：失败/超时/恢复、首片段与完成耗时分布、上游实际扣费。

这些是建议新增的指标，不是开物当前已达到的成绩。内容质量应采用规则、人工判断和实际结果多层验证；单一评测层无法覆盖全部问题。[Anthropic评测方法](https://www.anthropic.com/engineering/demystifying-evals-for-ai-agents)

也不建议为了显得先进就增加大量Agent或换更贵模型。固定业务流程可以先做好任务拆分、约束、证据和检查；增加复杂度要通过质量、延迟和成本实验决定。[Anthropic工作流与Agent设计](https://www.anthropic.com/engineering/building-effective-agents)

## 9. 现阶段应该怎样介绍产品

更准确的表达是：**“带账号档案和编导方法的短视频创作工作台，帮助你从想法、拆解、二创走到审稿与拍摄；内容可继续编辑和积累。”**

可重点展示真实档案承接、一条内容接着做、改稿与版本、真实素材优先、拍摄交付形式和反馈学习。不要用没有独立证明的“MCN专家级9.5分”“联网全部核实”“完整替代专业编导”“一键保证爆款”作为质量卖点。

用户最可能愿意续费的理由，是第二个月比第一个月更懂他的真实业务、表达和已有作品，而不是菜单继续变多。模型和Dify不是独占能力；作品、确认事实、采用稿、风格偏好与发布反馈形成的业务资产，才是更有积累空间的优势。当前这些基础已经存在，下一步需要证明它们确实减少改稿和操作。
