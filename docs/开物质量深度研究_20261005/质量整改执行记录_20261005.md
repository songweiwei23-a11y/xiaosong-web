## 第二阶段：知识库按任务分流（已完成，待部署）

**基线实测**（同一个脚本任务）：

| | 输入 token | 出第一个字 | 全部完成 |
|---|---|---|---|
| 查编导知识库（5 组 × 4 条） | 32,363 | 9.0～15.7 秒 | 15.3～24.7 秒 |
| 不查 | 8,333 | 3.5 秒 | 19.3 秒（这次回答更长） |

Excel 公式、局部改写这类任务，原来也照样带着整套检索。检索开关就是交给 Dify 的 `search_query`：传空就不检索（0 条、十几毫秒），**不用改工作流**。

现在：画布改一句、按资料修正、深度研究、偏好学习不查；自由对话只在问短视频相关的事时查；写脚本、选题、审稿、标题照常查。**这一轮要联网时检索词照常传**——线上工作流的联网节点可能也读 `search_query`，清空会让联网搜不到（`lib/kb-routing.ts`）。

上线后看两个数：自由对话的平均首字时间、Dify 账单里的输入 token。

## 第二阶段对比结果与决定（2026-10-05）

测试应用「开物-测试」只改知识检索（每组 4 条 → 2 条、相关度门槛 0.2），和正式「开物」同时跑 20 道题（研究的 13 道样题 + 夜间回归 7 个），共两轮：

| | 正式（4 条） | 测试（2 条 + 门槛） |
|---|---|---|
| 输入 token 中位数 | 33,115 / 33,118 | 21,266 / 21,266（少 36%） |
| 首字中位数 | 7.9 / 6.9 秒 | 7.4 / 7.0 秒 |
| 完成中位数 | 29.4 / 25.6 秒 | 30.8 / 22.7 秒 |
| 回归通过 | 2/7、3/7 | 3/7、3/7 |

机器指标上测试版只省成本、速度打平；产品方逐题看了两边答案，**认为正式版的回答更好，决定放弃测试版，正式检索设置保持不变**（每组 4 条、不设门槛）。「知识库按需检索」开关（lib/kb-routing 的 KB_ROUTING_ENABLED）同样保持关闭。

对比里顺带查出并修好了事实核对的一批误报（「常见误区」「夜市」「成都老乡」当地名、「拿起一块」当价格、配比百分比、模型自检清单里复述的年限、「没有用全网第一」当吹嘘），都写进了回归测试。
