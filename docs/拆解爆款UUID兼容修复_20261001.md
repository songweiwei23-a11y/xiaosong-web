# 拆解爆款 UUID 兼容修复

日期：2026-10-01，北京时间。

## 原因

正式站使用 HTTP 地址，浏览器没有提供仅安全上下文可用的 `crypto.randomUUID()`。此前新增历史记录时，拆解爆款和跨行业二创直接调用这个方法，导致创建历史编号时失败。拆解已经完成截图、口播识别和截图上传，但尚未发出 AI 拆解请求，所以不会产生拆解报告或扣除拆解次数。

依据：[MDN randomUUID](https://developer.mozilla.org/en-US/docs/Web/API/Crypto/randomUUID)、[MDN getRandomValues](https://developer.mozilla.org/en-US/docs/Web/API/Crypto/getRandomValues)。后者可在 HTTP 页面使用。

## 修复

- 增加 `lib/history-id.ts`：优先原生 UUID；原生方法不存在时，使用 `getRandomValues()` 生成符合 UUID v4 格式的历史编号。
- 拆解爆款、跨行业二创统一使用该方法；跨行业二创编号生成移入异常处理范围，失败也能结束加载状态。
- 历史记录的账号和档案隔离、幂等保存、权限与额度校验继续沿用原流程。
- 未更改页面设计或排版。

## 验证与上线

- TypeScript 类型检查通过。
- 5 个相关测试文件、47 项测试通过，包含缺少 `randomUUID` 的实际回退路径、连续生成编号不冲突，以及创作历史和服务端存档。
- 正式服务器构建成功，PM2 进程 3256435 在线，HTTP 200；317 个部署文件与本地 MD5 全部一致。
- 在正式站使用用户原来的 `下载 (2).mp4`（28.5 MB）完整重跑：画面提取、11 段口播识别、4 张拼图上传、AI 拆解均正常完成。
- 新报告为“爆款拆解报告·「怎么有效刷抖音」教学视频”，包含完整镜头拆解与当前店铺的 3 个选题；加载状态已结束，无拆解或存档错误。
