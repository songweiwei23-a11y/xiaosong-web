# 质量检查与发布数据反馈实施记录

本记录对应 2026-10-03 全面优化任务中的质量与数据反馈部分。代码已完成本地验证，未部署，未调用付费模型 API。

## 已落实

- 输出空白、只含标点、必要配比条目缺失，不能判为质量通过。
- 审稿检查明确的“优化后的完整脚本”正文；诊断报告引用的错误原文不会被算作最终稿。缺交付章节、空交付章节都判失败，不再回退检查原始报告。
- 年数按从业、本地、店龄分别匹配；明示的人设字段优先于故事中的旧说法。未知店龄不能借用从业年数。规则适用于可识别的中文年限语句，不等于通用事实核验。
- Dify 回归流只有正常结束事件且有正文才成功。任何上游错误、异常截断或损坏事件均失败，问题以 generation 类别记录。
- 固定回归从三个扩展到五个：餐饮创作方向、审稿、画布，以及美甲/小红书选题、家具/视频号开篇。新增样例验证必要交付章节。这是代表性规则集，不能宣称覆盖全部行业；真实运行仍会产生模型费用，本轮仅注入函数和合成流测试。
- 发布指标增加平台、观察时长、三秒留存率、投放情况，旧数据兼容。只在同目的、同平台、相近观察时间、同投放情况内进行参考排序；不同目标采用不同指标。未录入转化指标的作品不按零转化参与排名。
- 补充每千播放涨粉/咨询/成交指标，只统计同时填了播放和该指标的作品，空值不是零。零播放不作除法。
- 低完播率仅提示检查时长、受众与节奏，不再声称开头三秒没留住人；三条样本不视为验证有效。提示词和复盘页面同步降低结论强度。

## 字段接口

存储仍为 works.metrics JSON，无需新增数据库列或迁移：

```ts
platform?: string;          // 最多 40 字
observationHours?: number;  // 0–8760，小时，最多一位小数
retention3s?: number;       // 0–100，百分比，最多一位小数
paidPromotion?: boolean;   // 未填写是未知，不默认 false
```

METRIC_FIELDS 已包含观察时长和三秒留存。平台与投放情况由作品数据表单接入。汇总接口新增 byCohort、comparableCount、comparisonScope；原有字段保留，best/worst 现在只来自一个具备足够数据的可比组。指标函数导出 perThousand。

## 仍需验收或后续工作

- 浏览器页面的自动上报依赖调用方触发。生成连接直接失败的记录还应由统一生成链路记录，不能仅依赖有正文时的结果面板效果。
- 所有规则检查只说明所覆盖规则未命中，不表示作品事实完整正确或能直接拍。姓名、金额、引用来源、版权、行业特殊要求仍需逐步增加核验。
- 发布数据目前为用户手动录入。同组比较仍可能受投放金额、人群、视频长度、发布时间影响，只能作为试验参考。
- 复盘接口当前最多读取最近 200 条有数据作品；数量超过后需要分页聚合或数据库端统计。不会删除历史，但展示范围需进一步扩展。
- 扩展的五个夜间样例必须在部署后查看真实响应、耗时与费用，再按需要调整定时任务预算，不能用本地 mock 当作真实模型验收。
