# 高阶自由对话：联网、图片、文档和附件记忆

日期：2026-09-30 开发，2026-10-01 上线验收（北京时间）

## 已实现

- 保留原页面风格，新增图片/文件上传、拖拽、缩略图、原文件下载。
- 每条消息最多 6 个文件，每个文件不超过 10 MB。
- 支持 JPG/JPEG/PNG/WEBP/GIF、文字型 PDF、DOCX、XLSX、CSV、PPTX、TXT、Markdown、HTML、XML。旧版 Office 文件需另存为新格式。
- 图片原件保留，给模型的视觉副本自动缩小至最长边 1600 像素、350 KB 以内，避免 Dify Cloud 5 MB 请求限制；GIF 按静态帧识别。
- 文档通过 Dify 文档筛选器与正文提取器进入 Claude 模型。没有附件时提取器正常返回空列表，现有板块继续运行。
- 所有现有生成与追问沿用共用的 Dify 主应用「开物」和 Tavily 搜索节点，具备联网检索能力；自由对话显示实际搜索状态及来源。
- 长问题包含明确联网要求时，优先检索该要求，避免账号背景和前面的文件分析说明淹没搜索意图。
- 新上传时只发送本轮附件，避免旧图片干扰新文档；没有新上传时，追问携带本对话最近一批附件，最多 6 个。更早的原文件和对话仍保存在历史中；新对话不继承其他对话的附件。
- 附件描述、搜索来源随已有对话 JSON 保存，按账号和档案保留；刷新和换设备可以读取。原文件保存到专用私有桶 `chat-attachments`，读取接口校验登录用户及路径归属。
- 上传回执由服务器签名，阻止伪造其他账号的模型文件引用；文档只提供下载，不在网站域名内执行 HTML/SVG。
- 上传同时最多运行 3 个通道，缩短多附件等待；切换档案或对话时取消旧上传，避免文件串到新档案。
- 处理 Dify 完整替换答复事件，避免把最终正文重复追加；生成失败会向用户显示原因。

## 能力边界

常见图片、文档问答、联网来源、对话附件历史已实现。扫描型 PDF 的自动 OCR、文档内图表的视觉还原及超长文件的分段阅读尚未实现，不能宣称与 Claude 官网全部能力完全一致。此类材料可先上传清晰截图或拆分为较短的文字型文档。

文档正文不会自动进入所有档案的永久知识库；历史记录与本对话附件引用保留，模型仍受当前对话上下文窗口和上游可用性限制。

官方依据：[Dify 文件上传](https://docs.dify.ai/en/api-reference/files/upload-file)、[发送对话消息](https://docs.dify.ai/en/api-reference/chat-messages/send-chat-message)、[文档提取器](https://docs.dify.ai/en/cloud/use-dify/nodes/doc-extractor)。
