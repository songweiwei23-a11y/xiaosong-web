# 全板块一键承接验收

日期：2026-10-01。正式网站：http://122.51.234.155。

## 完成的行为

- 拆解、二创、审稿、选题、脚本、分镜、标题、开篇、高阶自由对话共 9 个内容目标统一承接创作信息。
- 带入原始方案、当前版本、主题、方向、人群、平台、精确时长、类型、结构、目的、风格、选定开头和拍摄设置。已有明确选择优先；缺失项依据原稿、档案和任务类型补齐。目标页等待档案读取完成后填表一次，之后不会覆盖用户手动修改。
- 设置写入生成请求及历史记录。后端在历史记忆之后追加本轮设置，降低旧内容替换当前方向的风险。刷新后从历史结果继续创作使用该结果保存的设置，而不是空表或当前另一条稿件的参数。“我的作品 / 进行中”的直接作品链接也从各环节历史恢复连续设置。
- 开篇和标题只改局部时保留完整稿件；继续审稿、写脚本、拆分镜仍获得完整正文。明确台词字段可恢复口播，策略卡和拍摄建议保留在参考信息中。
- 从其他文字内容进入拆解，自动选择文案模式，不再要求上传视频。文案模式不会宣称已观看画面或听到音频；实际视频分析仍需提供视频。
- 沿用原有界面风格，自动配置后可直接点生成。生成结果仍可能需要编辑和事实核验，不承诺模型输出必然等于用户预期。

## 自动检查

- Vitest：84 个测试文件，1727 项通过。
- TypeScript：`npm run type-check` 通过。
- 设置测试覆盖 9 个目标之间的 72 种有向组合、连续跳转、刷新后历史、旧记录补齐、单独二创方案、精确 37 秒、开头锁定、别名规范化以及非当前档案主题的推断。
- 这 72 种是自动检查，不代表逐一执行了 72 次线上 AI 生成。
- 另覆盖直接打开作品的脚本、审稿、分镜、标题、开篇 5 个入口，验证后续标题不会丢掉完整脚本和精确时长。

## 线上实测

测试使用一段专门编写的牛肉备菜文案，档案为“锦园地摊串串一元火锅”。显式设置：晒过程、火车节、人设型、视频号、37 秒、25-35 岁关注食材的本地顾客。测试稿与 AI 改写均不作为经营事实证明。

| 流程 | 检查结果 |
| --- | --- |
| 粘贴原稿 → 审稿 | 自动解析平台、时长、类型，直接生成审稿报告并保存历史 |
| 审稿 → 开篇 | 自动带入主题、原开头、开篇卡与连续设置，未重填字段即可生成 |
| 选择开篇 → 脚本 | 自动选中晒过程、人设型、火车节、视频号、37 秒和原人群，锁定所选开头，直接生成完整脚本 |
| 刷新审稿历史 → 选题 | 仍保留原设置，直接生成 5 条选题 |
| 脚本 → 分镜 | 自动带入 140 字完整口播，选择晒过程、视频号、37 秒，直接生成 2437 字分镜报告 |
| 审稿 → 文字拆解 | 自动选择文案模式并带入参考，不上传视频即可生成 4240 字报告；历史数量由 2 增至 3 |
| 脚本 → 标题 | 主题、原人群、创作参考和连续设置自动带入，生成按钮可用；本次只检查准备状态 |
| 脚本 → 二创 | 参考、目的及精确时长自动带入，开始二创按钮可用；本次只检查准备状态 |
| 直接打开作品脚本 | 自动恢复晒过程、人设型、火车节、视频号、37 秒、原人群，生成按钮可用 |
| 作品脚本 → 自由对话 | 自动预填 4151 字参考与继续创作请求，包含原稿、当前完整脚本、方向、人群、结构和时长，发送按钮可用；本次只检查准备状态 |

实际分镜与文案拆解均已完成；测试生成历史保留。

## 发现的内容质量问题

模型仍补写了原稿没有提供的“早上六点采购、下午三点半切肉”“刀用了九年”等经营细节。分镜报告还出现“拍摄前别洗手、不要戴手套”等不妥建议。这些不是已核实事实或经过审核的操作规范，不能直接采纳。本次修复针对跳转、自动填表和信息承接；上述模型内容质量问题单独向用户汇报，由用户判断后续处理范围。

发布切换期间旧页面发生一次 ChunkLoadError；读取日志确认是旧资源块失效，重新加载新版后页面和承接恢复正常。使用正式版时应先刷新现有旧页面。
