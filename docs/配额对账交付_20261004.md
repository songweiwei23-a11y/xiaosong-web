### 可信完成证据与管理员对账

- 新表 creation_completion_evidence 保存完整服务端结果、SHA-256、原请求指纹、功能、实际终止事件、消息编号、字符数、实际收到的 token/时延/价格元数据。
- 三入口成功后先写完成证据，再确认额度；写证据和确认均可用同请求幂等重试。
- 普通登录用户与匿名用户不能写/读证据表，不能调用证据或对账 RPC。证据不接受用户提交的历史记录作为成功证明。
- `GET /api/admin/quota/reconcile`：管理员读取最多 50 条待处理编号及证明元数据，不返回完整正文。
- `POST /api/admin/quota/reconcile`：requireAdmin；默认 dryRun。省略 requests 时，仅选取有完成证据的待处理请求，最多 50 条。
- 指定批次格式：`{"requests":[{"userId":"UUID","requestId":"生成编号"}],"dryRun":true}`。只有显式 `dryRun:false` 执行确认。
- 对账核验同账号/请求/功能/原请求指纹、非空正文、SHA、字符数及成功终止。过期但无证据保持 unknown，不扣次数。
- 对账确认与 admin_logs 审计写入同事务；日志失败整批回滚。重复对账不多扣，不重复写使用事件。
- `lib/dify-task.ts` 已补完整结束标记与实际元数据返回，避免前采把截断的可解析 JSON 当成成功。

### 持久创作交接

- 修复 SQL settings 合并顺序：新环节只改变指定字段，保留原来的目标人群、结构、时长等设置。
- 同作品最早 originContent 保留；每次交接快照不可改写或删除。
- 同 requestId、原始 payload、branch 重试返回同一快照，响应丢失不会重复造作品；变更内容/分支标记复用 ID 拒绝。
- 分支先验证父作品账号与档案，再创建独立作品；不会改变父作品。
- 多选方案不创建虚假作品；分支多选不残留父 workId。
- target=/dashboard/topic 不复用旧作品，也不提前创建新作品；完整需求仍保存，选择单条跳到 script 时再创建作品。
- RPC 与直接表 INSERT 的 RLS 均拦截跨账号、跨档案及伪造 user_id。
