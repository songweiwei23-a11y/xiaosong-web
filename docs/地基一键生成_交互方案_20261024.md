# 地基一键生成：交互方案（2026-10-24，待选定）

> 需求：用户完成任何途径的建档后，立刻要求一键生成「账号定位、创作简报」等地基；生成在一个大弹窗里同时运转；完成后提示「已完成」，并可点击跳转查看各个地基的结果。
> 本文先给出三个可选方案，供选定后再实现。所有事实都来自当前代码，标注了出处。

---

## 一、先说代码里的实际约束（决定了方案的边界）

| 事实 | 依据 | 对设计的影响 |
|---|---|---|
| 创作简报依赖账号定位：没有定位，简报接口直接拒绝 | `lib/assistant/tools.ts` 的 `propose_brief` 先查定位，没有就报「请先派账号定位」 | 定位和简报**不能真正同时跑**，简报必须排在定位后面 |
| 行业建议必须先问「账号目的」和「当前阶段」 | `lib/assistant/board-dispatch.ts` 第 206 至 209 行，缺了就不能派 | 行业建议不能纯一键，要么给默认值，要么先问两个选择题 |
| 定位、简报、行业建议共用「定位」额度 | `lib/config/plans.ts` 的 TASK 映射：三者都归 `positioning` | 一键生成会一次扣多份额度，必须在弹窗里说清楚、并先检查额度够不够 |
| 只有少数板块的结果由服务端持久保存（关页也会保存） | `lib/creative-history.ts` 的 `DURABLE_CREATIVE_TASKS`：拆解爆款、跨行业二创、创作方向、内容规划 | **账号定位、创作简报不在名单里**。用户在生成途中关掉页面，结果可能丢失。做这个功能前必须先补上 |
| 「先打地基」三步：建档 → 账号定位 → 创作简报 | `lib/setup-progress.ts` | 地基的完成状态已有统一判断，弹窗可以直接复用，不需要另起一套 |
| 地基未完成时，生成创作结果会被拦截 | 10 月 23 日上线的地基门槛（`lib/foundation-gate.ts`） | 弹窗就是把这道门槛变成一个引导入口，而不是只给一句报错 |

**结论**：「同时运转」在实现上只能做到两条线并行——一条是「定位 → 简报」，一条是「行业建议」（它不依赖定位，需要先确认是否真的不读取定位结果，待核实）。还有一个前置条件：**先把账号定位和创作简报加入服务端持久保存**，否则方案 B、C 都不可靠。

---

## 二、触发时机（适用于任何建档途径）

建档的途径有：手动新建、前采建档（访谈导入）、助理代建档案。三者最终都会产生一条档案。

**建议用「状态驱动」，不用「事件驱动」**：
- 弹窗的出现条件只看状态：「存在档案，且账号定位或创作简报缺一项，且本次会话还没有完成或跳过过」。
- 这样不管用哪种途径建的档，只要状态满足就会出现，不会漏掉某个入口。
- 挂在全站布局里（和「生成结果没保存」提示同一层），任何页面都能触发。

## 三、三个方案

### 方案 A：向导式（一步一步，串行清单）

弹窗像安装向导，三步依次完成，每一步完成才进入下一步。

```
┌──────────────────────────────────────────────┐
│  先打好地基（约 X 分钟，消耗 2 次定位额度）     │
│                                              │
│  ✓ 1 建档案                       已完成     │
│  ● 2 账号定位                     生成中 ▮▮▯  │
│  ○ 3 创作简报                     等待定位完成 │
│                                              │
│  [ 后台运行，先去做别的 ]        [ 取消 ]     │
└──────────────────────────────────────────────┘
```

- **流程**：点「一键生成」→ 依次跑定位、简报 → 完成后显示结果卡片，每张卡一个「查看」按钮。
- **优点**：最简单，只有一条线，好实现，不会出现并发问题。
- **缺点**：和「同时运转」的要求不符，时间更长。行业建议不在里面，要单独做。

### 方案 B：并行泳道（推荐）

弹窗里有两条泳道同时跑：一条「定位 → 简报」，一条「行业建议」。每条泳道有自己的进度，可以最小化成右下角的小浮条，用户可以继续使用其它页面。

```
┌──────────────────────────────────────────────┐
│  一键生成地基                         [ 最小化 ] │
│  消耗：定位额度 3 次（定位 1、简报 1、行业建议 1） │
│                                              │
│  泳道 1  账号定位 ──► 创作简报                  │
│          ● 定位  生成中  01:23                  │
│          ○ 简报  排队（等定位完成）              │
│                                              │
│  泳道 2  行业建议                              │
│          ● 生成中  00:48                       │
│                                              │
│  生成过程中关掉页面，结果也会保存（需先完成持久化）  │
└──────────────────────────────────────────────┘
```

最小化后的浮条：
```
┌────────────────────────┐
│ 地基生成中 1/3 完成  ▮▮▯ │  点击展开
└────────────────────────┘
```

- **流程**：点「一键生成」→ 两条泳道同时开始 → 任一完成就在泳道里显示「查看」→ 全部完成后弹出完成面板。
- **优点**：符合「同时运转」的要求，等待时间最短；最小化后不挡住用户继续工作。
- **缺点**：要做全局的运行状态管理（浮条、刷新后恢复进度）；需要先做服务端持久化。

### 方案 C：分步确认（用户掌控）

先只生成定位，弹窗展示定位结果，用户看完再决定要不要继续生成简报和行业建议。

```
第 1 步：定位生成完成 ✓   [查看定位]
第 2 步：要生成创作简报吗？约消耗 1 次定位额度
         [ 生成简报 ]  [ 以后再说 ]
```

- **优点**：用户能先看到定位结果，觉得可信再继续，额度也更可控。
- **缺点**：不是「一键」，多一次点击；与「强制、一键」的要求相悖。

## 四、完成态与跳转（三个方案共用）

全部完成后，弹窗切换为完成面板：

```
┌──────────────────────────────────────────────┐
│  ✓ 地基已完成                                   │
│  这些结果已经保存，之后生成内容会自动用上它们。     │
│                                              │
│  账号定位   六个方面，已生成     [ 查看 ]         │
│  创作简报   已生成               [ 查看 ]         │
│  行业建议   已生成               [ 查看 ]         │
│                                              │
│  [ 开始创作 ]                  [ 关闭 ]          │
└──────────────────────────────────────────────┘
```

- 「查看」跳转到对应的结果页（账号定位页、创作简报页、行业建议页），并在弹窗中标记「已完成」。
- 「开始创作」进入选题页，并把地基完成的状态带过去（`lib/foundation-gate.ts` 此时放行）。
- 查看结果后再回到首页，不需要重新生成。

## 五、异常与边界

| 情况 | 处理 |
|---|---|
| 额度不够 | 开始前检查，不够就禁用「一键生成」，显示需要的次数和升级入口，不先扣一部分 |
| 其中一步失败（比如定位成功、简报失败） | 只重试失败的那一步，已完成的保留，不重新生成整套 |
| 生成途中断网 | 服务端完成的结果保留；本机显示「网络断开，已完成 X 项，恢复后可继续」 |
| 生成途中关掉页面 | 需要先完成持久化（见第一节）。未完成持久化前，只能提示「请保持页面打开」 |
| 同一档案重复点击 | 运行中禁用按钮；已有完整地基时不显示弹窗 |
| 有多个档案 | 只针对当前档案，顶部显示当前是哪个档案，切换档案时弹窗关闭并重新检查状态 |
| 用户想跳过 | 方案 B、C 允许「稍后再说」，但顶部保留一条提示直到完成；强制程度见第六节第 1 题 |

---

## 六、需要你定的 5 个问题

1. **强制程度**：弹窗是「必须开始一次」才能关（硬强制），还是「可以先关，但之后每次进入都会提示」（软强制）？我的建议是软强制：硬强制会让不愿意花额度的用户直接离开。
2. **额度**：一键生成会扣定位额度（约 3 次）。是否接受，还是只生成定位、简报按需再开？
3. **行业建议**：是否纳入一键？纳入的话，「目的、阶段」用默认值，还是先弹两个选择题？
4. **最小化**：是否允许最小化后继续使用？（方案 B 推荐允许）
5. **完成后的默认跳转**：完成面板是否直接打开账号定位页，还是停留在面板里让用户自己选？

## 七、实施前置工作与工期（粗估）

| 项 | 说明 | 估算 |
|---|---|---|
| 账号定位、创作简报加入服务端持久化 | 把它们加入 `DURABLE_CREATIVE_TASKS` 并验证关页后仍保存 | 1 至 2 天 |
| 地基状态全局化 | 弹窗、顶部提示、完成状态共用一份状态（`useSetupProgress` 已有基础） | 1 天 |
| 方案 A 弹窗（串行） | 三步、进度、结果卡片、查看跳转 | 2 至 3 天 |
| 方案 B 弹窗（并行泳道） | 在 A 的基础上增加两条泳道、最小化浮条、刷新后恢复进度 | 额外 2 至 3 天 |
| 方案 C（分步确认） | 复用 A 的结果卡片，增加确认步骤 | 额外 1 天 |
| 测试与验收 | 单元测试覆盖状态机；真机走查（手机和电脑各一次） | 1 天 |

## 八、验收标准（三个方案共用）

- 任何途径建档后，地基未完成时，下一次进入任何页面都能看到弹窗或提示。
- 额度不够时，不会扣任何次数。
- 一键完成后，所有结果都能在对应页面看到，刷新后仍在。
- 生成途中关掉页面，结果仍然保存（方案 B、C 的前提）。
- 完成后，「开始创作」可以直接生成内容，不再被地基门槛拦截。
- 指标：新用户从建档到第一份结果的时间，较之前缩短（需要上线前后各统计一周）。

## 九、我的推荐

**方案 B（并行泳道）+ 软强制 + 最小化允许**。理由：
1. 它是唯一真正满足「同时运转」的方案；
2. 最小化让用户在等待时仍能用别的功能，不会因为强制弹窗而离开；
3. 实现量比 A 多出的部分，主要是状态管理，而状态管理本来也是后续功能需要的。

实施时的做法（2026-10-24 已选定方案 B 并实现）：生成放在服务端任务里进行，结果直接写进账号定位表，不依赖页面是否还开着，所以第七节第一项不再需要把板块加入持久化名单。
