# 「开物 · 截屏带入」浏览器插件（2026-11-01，11-02 改成一键采集）

把对标账号的主页、作品、点赞、热门作品评论带进开物，按做账号定位的维度把对方的定位倒着拆一遍。代码在 `browser-extension/kaiwu-capture/`，网站上的下载包是 `public/kaiwu-capture.zip`（改了插件代码要重新打包；它被 git 忽略，同步脚本按文件夹上传，会跟着部署）。

2026-11-02 产品方定：可以自动化采集，「一切后果我来承担」。

## 用户怎么用

1. **装插件**（只一次）：开物「对标 & 热点」页没检测到插件时会提示，点「下载插件」照四步装好。装的是旧版会提示更新。上架商店以后变成点一下「添加」。
2. **在开物里粘贴主页链接**：页面最上面「粘贴对标账号主页，一键拆解」，粘贴浏览器地址栏的主页链接，或者抖音 App 里「分享主页 → 复制链接」的整段文字，点「一键采集并拆解」。
3. **等大约 1 分钟**：插件新开一个标签页打开这个主页，自动往下翻、读作品和点赞，取点赞最高 6 条的封面，再依次打开最火的 3 条读数据和评论。读完自动切回开物（等的时候点去了开物的别的页面也没关系，会自己转回对标页；开物那个标签页关了就新开一个）。
4. **自动开拆**：开物按主页链接对上对标账号（没加过就自动新建），把数据放进它的拆解区，直接开始拆。

也可以在抖音主页上点右下角开物面板的「一键采集这个账号」，或者点浏览器右上角的插件图标，效果一样。只想截某一屏，面板上有「只截当前屏幕」，快捷键 Alt+Shift+K。

**登录抖音网页版能读得更全**：没登录时抖音只给看主页前十几条作品、每条五六条评论，报告里会写明「数据不全」。

## 拆出来的报告（lib/benchmark-analysis 的 BENCHMARK_FRAMEWORK）

和账号定位方案（lib/positioning-standards 的 OUTPUT_FULL）同一套维度，倒着拆：材料清单 → 核心结论 8 条 → 一句话定位（倒推）→ 六维（人设、用户、内容、呈现、风格调性、变现）→ 数据表现（点赞分布、爆款共同点、置顶、评论区关心什么）→ 记忆点 → 差异化（常规A + 变量B）→ 账号五件套 → 自洽检验 → 他的软肋 → 对我们的参考 → 待核实。每条结论要写依据（主页信息、作品清单第几条、热门作品几的评论区、封面）。

## 自动化守的底线

| 做 | 不做 |
|---|---|
| 编导发起后（开物里粘贴链接、面板或插件窗口的按钮）才跑，一次一个账号 | 不在后台定时跑，不批量跑多个账号 |
| 翻页、换作品之间随机等 1.5～4 秒 | 不连续快速请求 |
| 读页面上显示出来的主页信息、作品标题、点赞、四个数、评论文字和点赞数 | 不调抖音的数据接口，不读 Cookie，不收评论人昵称、头像、地区 |
| 遇到验证码就停：已经读到作品的，先把读到的带回开物开拆，报告里写明停在哪（0.3.1 起，免得卡在半路）；一条都没读到的，提示编导自己在页面上完成验证，再点「继续采集」 | 不代解验证码，验证后也不自动接着跑 |
| 作品最多 60 条、热门作品 3 条、每条评论 20 条、截图加封面 9 张 | |
| 封面只从抖音图片域名取（douyinpic.com），截图只截发起采集的那个标签页、而且它在前台 | 不截别的网站 |
| 数据存在编导自己电脑上，带进开物后清空；开物只保存拆解报告 | 不传到开物以外的地方 |

权限：activeTab、storage、unlimitedStorage；网站权限只有 www.douyin.com（跑采集）和 *.douyinpic.com（取封面）。测试 `tests/capture-extension-20261101.test.ts` 守着上面这些（发起方式、随机等待、验证码就停、上限、不碰 Cookie 和接口、读评论不碰昵称、权限不多出来），也守着开物这边的校验：网页来的数据按白名单字段收、超量截断。

**风险（产品方已知晓并承担）**：抖音的用户协议不允许自动化读取；页面改版时读取规则会失效（读不到会提示「抖音改了页面」，要来改 collector.js 里的 data-e2e 标记）；采得太频繁，编导自己的抖音账号可能被要求验证或限制。

## 上架 Chrome / Edge 扩展商店（要产品方用自己的开发者账号提交）

- **Edge 加载项**（免费）：partner.microsoft.com 注册开发者 → 提交 `kaiwu-capture.zip`。
- **Chrome 应用商店**（一次性注册费 5 美元）：chrome.google.com/webstore/devconsole 注册 → 上传 zip。
- 要准备：插件图标（128×128）、两三张截图、一段说明、隐私说明（读取的内容只交给开物、本机存储、带进开物后清空；不收集评论人身份信息）。
- 商店审核会看自动化读取第三方网站这一点，可能要求补充说明或不通过；不通过就继续用「开发者模式」安装。
- 上架以后，开物页面的安装提示改成直接跳商店的「添加」链接。
