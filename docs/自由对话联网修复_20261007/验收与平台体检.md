## 深度研究是否受到影响

研究流程仍是拟计划、用户确认、分题检索、读正文、写分节、写结论、引用核对、保存历史。没有增加原计划的搜索词数量，没有改变恢复、取消和配额流程。

新增检索质量逻辑与自由对话共用；研究独立提示词保留。官方 Markdown 文档按原文读取，不用 HTML 清洗误删参数占位符。既有正文缓存和来源编号继续使用。

真实验收包含两层：

- 正式 Dify 合成研究：三轮搜索、三个分节和汇总，读取 LLM、Variable Assigner、Knowledge Retrieval 三份官方正文并组装报告。
- 正式网站隔离账号：创建计划，等待计划落库，确认两个子问题，等待研究完成，恢复来源和报告，再由第二账号检查隔离。研究额度最终 `used=1`、`pending=0`。

功能通路通过，但人工检查发现：报告把“不同 conversation 不继承上下文”进一步写成“会话结束会清空记忆”。该存储删除结论没有对应原文支持，不能算事实核实通过。数字匹配零异常、引用编号有效，也不能证明语义正确。

## 后续优化建议与验收标准

1. **先补事实约束，再增加文案技巧。** 将确认的价格、年限、地域、服务范围和真实故事做成唯一事实清单；未知信息生成中性动作表达。档案事实与模型创意建议分别标记，跨板块继续创作时同时携带，不能把建议升级为已确认事实。验收：缺少免费政策时不出现免费承诺，居住年限不变成店龄，顾客经历没有来源不成为可发布台词，未提供县名不补造县名。
2. **审稿分别评创作与事实。** “写得有吸引力”和“可以公开发布”应分别判断。验收：改稿不能引入原稿、档案之外的新经营事实；事实缺口要明确标出。
3. **研究核对引用的支持范围。** 保留分节与汇总之间的推断标记，加入语义核验；不能只检查编号和数字字符串。验收：跨会话隔离不被改写为数据库删除，付费投放能力不被写成自然推荐规则。
4. **按板块控制输出预算与等待时间。** 先定位耗时节点，再调整输出规模，长方案分段交付且可继续。验收：给出各板块成功率、首字和总耗时的多次样本，超时保留可恢复状态，不能只靠一次接口成功。
5. **完善自动质检。** 补充“免费出方案”等同义经营承诺，识别模板故事与真实故事的区别，减少“唯一行动指令”这种非广告表达的误报。验收：以上实际失败样本能准确告警，合规解释不被误判成发布文案。
6. **补页面端验收。** 浏览器连接恢复后，实际点击每个方案的跳转，检查档案、方向、人群、开头、结构和锁定正文是否承接，再检查刷新、断网和换账号。后端测试不替代这一层。
