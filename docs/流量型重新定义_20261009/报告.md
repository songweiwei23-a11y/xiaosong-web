# 流量型重新定义：错在哪、什么是大流量、改了什么

日期：2026-10-09

## 一、结论

1. 「流量型 = 聊观点」是错的。聊观点拿不到大流量。
2. 聊观点归人设型：观点要连着自己的经历，才立得起人设。
3. 流量型的主力打法应当是大众入口的打法：反认知、冷知识、借势热点、地域差异、街头采访、整蛊反转，以及三十六计里标了流量型的几计。
4. 代码、测试、Dify 系统提示词源文件、知识库源文件中的对应说法已全部改掉（清单见第五节）。
5. 还没完成的：线上开物（Dify）第 29 版尚未发布，知识库修正文档尚未上传。原因和你需要做的事见第六节。

## 二、错误是怎么来的

错误出在两处资料，代码又照着它们写。

| 来源 | 原说法 | 问题 |
|---|---|---|
| 代运营从0到1创作SOP（库5） | 「流量→聊观点」，流量型配比「聊观点 / 挑战 / 热点」 | 把观点当成了流量的来源 |
| 实体店 / 娜家烤肉选题SOP（库5） | 「模式D · 聊观点型」，「引发站队争议，扩大流量，主力流量型」 | 同一个错误，还写成了"主力" |
| 选题示例卡片（库5） | 脚本「聊观点」+ 目的「流量型」 | 把组合固定成了例子 |
| 代码 `lib/content-roles.ts` 的 `defaultRoleOfScriptType` | 脚本类型含「观点」→ 默认「流量型」 | 把错误变成了默认行为：用户选聊观点，系统就按流量型去写 |
| 代码 `ROLE_SPECS.流量型` | 主力是聊观点；结构是观点并列、观点正反、争议开篇 | 流量型的结构整个是观点句式 |
| Dify 系统提示词第 28 版 | 「流量型：主力是聊观点、泛知识和起号打法」；「聊观点型（多为流量型）」 | 线上模型因此把观点当流量来写 |

脚本类型和目的是两件事。泛知识（大众入口）是流量型，专业难题是变现型，这一点原本就对；错的是把「观点」这种脚本类型直接等同于流量目的。

## 三、什么是大流量

### 3.1 定义

大流量：视频带来的**非关注用户**播放，即平台推给从没关注过账号的人的那部分。

它不等于：
- 粉丝数多。账号粉丝多少对陌生人的推荐影响很小，粉丝多的账号也未必能拿到大流量。
- 某一条视频"爆了"。大流量是可以反复拿到的能力，靠的是内容本身。

### 3.2 机制（第三方资料整理，不是平台官方说明）

本次用网络检索了 2026 年抖音和 YouTube 的推荐机制资料。结论如下，置信度说明写在括号里：

- 平台对新视频做分层测试：先发给一小批人，表现好才进入下一层更大的推荐池。（方向一致，多家资料都这么说）
- 进入下一层主要看：第一秒能否留住人（前几秒的留存）、完播率、点赞、评论、分享，以及是否带来关注。（方向一致）
- 初始测试的规模，资料里的数字从几百到几千不等，互相矛盾。（不作为事实使用，报告和提示词里都不写具体数字）
- 账号粉丝数对陌生人推荐的影响较小。（方向一致，但没有平台官方数据支撑）

### 3.3 由此推出的判断

能拿大流量的内容要同时满足三件事：

1. 第一秒有钩子：反差、问题、冷知识，陌生人一眼知道"这跟我有关"或"这很奇怪"。
2. 陌生人看得懂：不用行业黑话，不需要先认识你。
3. 看完或互动：完播、分享、评论，让平台推给下一层。

观点类内容在第 1 条和第 2 条上都弱：观点需要先认同你这个人，陌生人没有理由停下来。所以聊观点主要靠已有受众，它的正确位置是人设型。

## 四、新的定义

### 4.1 三种视频

| 目的 | 让谁看到 | 主力打法 | 结尾（只选一个） | 看什么 |
|---|---|---|---|---|
| 流量型 | 陌生人 | 反认知、冷知识、借势热点、地域差异、街头采访、整蛊反转、反向操作、拟人化等 | 关注或评论 | 非关注播放占比、完播率、分享、新粉 |
| 人设型 | 看过的人 | 讲故事；观点立场（观点连着经历） | 关注或看主页 | 主页访问、关注、"就冲你这个人" |
| 变现型 | 目标客户 | 教知识、晒过程 | 私信、到店、留资，三选一 | 咨询、线索、成交、复购 |

### 4.2 流量型的脚本结构（每个都有骨架）

- 反常识开篇：反常识结论（"你以为……其实……"）→ 大众熟悉的常规做法 → 实测或反证 → 一句话收住
- 冷知识（第36计）：一个让人意外的事实 → 为什么会这样 → 和每个人的关系 → 一句反问
- 反向操作（第1计）：常规A → 反向B → 真实反应/结果
- 借势点评（第12计）：热点事实 → 专业拆解 → 判断/建议 → 回到用户
- 地域差异（第31计）：A地的做法 → B地的做法 → 差异的原因 → "你那边是哪种"
- 街头采访（第35计）：一个问题 → 多人回答（有反差）→ 专业收尾
- 整蛊反转（第16计）：铺垫 → 误判 → 反应升级 → 揭晓

### 4.3 人设型里的观点

- 观点立场：亲身经历 → 我的判断 → 为什么这么看 → 邀请你怎么看

观点并列、观点正反、争议开篇这三种旧结构，现在都挂在人设型下，并要求论据来自自己的经历。

### 4.4 脚本类型到默认目的

| 脚本类型 | 默认目的 | 说明 |
|---|---|---|
| 聊观点 / 话题 / discuss | 人设型 | 原先是流量型，已改 |
| 讲故事 / story | 人设型 | 不变 |
| 教知识、晒过程、其余 | 变现型 | 不变；泛知识的教知识可以手动改成流量型 |

默认目的只是默认，用户可以改。

## 七、为什么不直接用一句「流量型不是聊观点」了事

提示词要让模型知道**怎么做**，而不只是**不要做**。所以这次同时给了三样东西：

- 流量型应当怎样拍（结构骨架，每个都标了对应的三十六计）
- 观点应当归到哪里（人设型，附观点立场骨架）
- 每种目的的指标和结尾（让模型能判断一条稿子是不是跑偏了）

这样模型在没有明确目的时，也不会默认走回聊观点。
