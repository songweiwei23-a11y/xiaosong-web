# 02 板块任务书（2026-10-30）

每个板块写清：使命、上游输入、下游输出（契约字段见 00 文档）、守则、已知问题、验收标准。

契约字段：`bigType`（四大脚本 / 36计）、`kind`（四大脚本下的类型）、`structure`（具体结构全名）、`purpose`（流量型 / 人设型 / 变现型）、`task`（这一跳的任务）、`elements`（爆款元素）、`source`（来源）。

---

## 根部（由另一个会话实现，这里只写它要满足的接口）

### 内容规划
- **使命**：按月把内容分配到三种目的（流量、人设、变现）的比例上，并给出每个目的下用哪一大类、哪些结构。
- **上游**：档案、定位、内容定位（配比、系列）、上月发布记录。
- **下游**：每个方向卡要求的目的和大类。
- **守则**：不写具体选题，不写具体拍法；结构只给名字和比例，不展开。
- **已知问题**：配比与结构的搭配依赖另一个会话的实现，目前工作区有未提交改动。
- **验收**：输出的每个目的都能对应到大类和结构，且比例与内容定位一致。

### 创作方向
- **使命**：把内容规划的目的落成方向卡：每个方向一个主张，写明目的、任务、大类、结构、拍法。
- **上游**：内容规划、定位、简报。
- **下游**：选题的 `purpose`、`task`、`bigType`、`structure`、`source`。
- **守则**：一个方向只归一个大类；不写具体台词；任务要能被选题直接执行。
- **验收**：每张方向卡都有完整的契约字段，任务是一句能被选题执行的话。

---

## 中部：选题（由我实现契约）

### 选题
- **使命**：把一张方向卡落成若干可拍的题。每题守住方向的目的和结构，并融入爆款元素，让题有切入点。
- **上游**：方向卡（`purpose`、`task`、`bigType`、`structure`、`source`），定位，档案。
- **下游**：每个选题标题后面带上契约字段，跳到脚本时整组带过去。
- **守则**：不改结构和目的；题目是「谁、遇到什么、怎么拍」，不是台词；爆款元素只用来设计切入，不硬塞。
- **已知问题**：
  - 打法行写的是类型头，解析器认不出具体结构（已修，未提交）。
  - 跳转时只带整批结果的设置，整批会被跳过（已修，未提交）。
- **验收**：每个选题都能解析出 `bigType` 和 `structure`；结构与方向卡一致；真实模型跑一次，题目守住结构。

---

## 叶部：脚本、分镜、包装板块

### 脚本
- **使命**：按选题的结构写成可拍的台词和策略卡，守住目的和任务，CTA 按目的给。
- **上游**：选题的契约字段（`bigType`、`kind`、`structure`、`purpose`、`task`、`elements`）、定位、档案。
- **下游**：脚本正文（台词一句一行）给分镜、标题、开篇、审稿。
- **守则**：
  - 结构由契约决定，不由模型自选。
  - 说话人：出镜人用「我」，不用身份称呼指自己（见 creative-craft 的说话人规则）。
  - 采访只在采访是主要做法时启用，顺带的只记在执行建议里。
  - 不把内部规则抄进正文（已观察到输出开头出现「【本轮内容落实规则】」，需要去掉）。
- **已知问题**：说话人主语被删（已修）；采访模板误触发（已修）；规则抄进正文（未修）。
- **验收**：台词按结构走；出镜人用「我」；没有内部规则抄进正文；真实模型跑一次，问句和采访标记为零（除非结构本身是采访）。

### 分镜
- **使命**：把脚本台词拆成镜头，每个镜头有画面、台词、时长和拍摄要点。
- **上游**：脚本正文、拍摄条件（档案）。
- **下游**：镜头表给后期和拍摄。
- **守则**：台词与脚本逐字一致，不改写；画面只写拍得到的动作，不补未发生的反应。
- **验收**：台词与脚本一致；时长相加与总时长一致。

### 标题封面
- **使命**：从选题和脚本出标题，标题守住目的（流量型标题要有爆款元素，人设型标题用第一人称）。
- **上游**：选题、脚本、契约字段。
- **下游**：标题列表给发布。
- **守则**：不改结构和目的；标题不编数字和经历。
- **验收**：每条标题能对回选题的目的和结构。

### 开篇钩子
- **使命**：为脚本写开头几句，钩子与结构一致（例如聊观点的开头是观点，教知识的开头是问题）。
- **上游**：脚本、契约字段。
- **下游**：开头原话（一句一行，可直接念）。
- **守则**：开头原话与脚本正文衔接，不另起一个结构。
- **验收**：开头能直接念；与脚本结构一致。

### 审稿
- **使命**：检查成稿的事实、现实规则、结构执行和说话人，只做小改，不整篇重写。
- **上游**：成稿、档案（事实依据）、契约字段。
- **下游**：改好的稿子和改动说明。
- **守则**：只改标出的几处；无依据的数字、经历换成【待确认】。
- **验收**：改动范围清楚；结构和目的没有被改掉。

## 周边板块

### 账号定位
- **使命**：定人设、人群、货的边界，给后面所有板块一个底。
- **上游**：档案。
- **下游**：定位全文（给内容定位、简报、选题参考）。
- **守则**：人设标签用档案里的身份原词，不另起称呼（已修）。
- **验收**：人设标签与人设事实卡一致。

### 商业定位
- **使命**：定变现路径和成交逻辑，供变现型方向和成交理由引用。
- **上游**：账号定位、档案。
- **下游**：变现路径、成交理由的依据。
- **守则**：不编成交数字和承诺。
- **验收**：每条变现路径都能在档案里找到依据。

### 内容定位
- **使命**：定内容方向、系列、三种视频的配比，供规划和方向引用。
- **上游**：账号定位、商业定位。
- **下游**：系列和配比（给内容规划、创作方向）。
- **守则**：系列要能被下游找到（已有截断保护）。
- **验收**：系列完整；配比合计 100%。

### 创作简报
- **使命**：把定位压成下游能用的摘要，不生产新结论。
- **上游**：账号定位、商业定位、内容定位。
- **下游**：简报给所有创作板块做背景。
- **守则**：摘要要保留定位里的身份原词和事实。
- **验收**：简报里的事实都能回到定位原文。

### 行业建议
- **使命**：给起号和变现的阶段性建议（药方）。
- **上游**：定位、作品数据（如有）、用户填的阶段和目的。
- **下游**：建议给用户和起号方案。
- **守则**：不编数据；没有数据就说没有。
- **验收**：建议按阶段和目的给出，没有凭空的数字。

### 起号方案
- **使命**：把内容定位的方向打开成起号阶段的具体打法（36 计或四大结构）。
- **上游**：内容定位、配比。
- **下游**：起号阶段的结构列表。
- **守则**：结构只用注册表里有的名字。
- **验收**：每个打法都能在注册表里找到。

### 成交理由
- **使命**：列出变现型可用的成交理由，并判断每条在这家店成不成立。
- **上游**：档案、店铺特色。
- **下游**：变现型方向和脚本引用。
- **守则**：不编店铺没有的理由。
- **验收**：每条成交理由都有店铺依据或标为不适用。

### 知识库查询
- **使命**：从知识库里找依据，回答创作问题。
- **上游**：用户问题。
- **下游**：带出处的回答。
- **守则**：回答要标出处；找不到就说找不到。
- **验收**：每条回答都有出处。

### 对标分析
- **使命**：拆解对标账号，说明哪些可以借、哪些不能借。
- **上游**：对标材料。
- **下游**：可借鉴的结构和元素。
- **守则**：结论要说明依据来自哪份材料。
- **验收**：每条结论有材料依据。

### 拆解爆款
- **使命**：把一条外部爆款拆成可复用的结构卡，映射到注册表里的大类和结构。
- **上游**：爆款文案。
- **下游**：结构卡（给二创和方向参考）。
- **守则**：只拆结构，不抄原文。
- **验收**：结构卡映射到注册表里的一个结构。

### 跨行业二创
- **使命**：借外行的爆款骨架，换成自己的人货场，保留原结构名。
- **上游**：拆解结果、档案、店铺信息。
- **下游**：二创稿。
- **守则**：结构名保留；人货场换成自己的。
- **验收**：二创稿守住原结构，人货场是自己的。

### 前采提取
- **使命**：把客户访谈原话提取成档案字段，剔掉策划稿章节。
- **上游**：前采记录。
- **下游**：档案字段（给定位和所有板块）。
- **守则**：只提取客户说过的，不编。
- **验收**：每个字段都能回到原话。

### 自由对话、开物助理
- 不在这次树的范围内，只需要确保它们读取的档案和定位与树一致。

## 测试分工

- 单元测试：契约字段的解析和格式化（每个字段都有用例）。
- 真实模型探针：每一跳跑一次，检查是否守住结构和目的。
- 全站测评：另一个会话在干净 worktree 里做，覆盖所有板块。
