# 00 总体设计：内容创作树（2026-10-30）

## 一、两个大类

整棵树顶层只有两个大类，每条内容只归一个大类（不叠加）：

| 大类 | 管什么 | 旗下结构 |
|---|---|---|
| **四大脚本** | 话怎么讲 | 四个类型（教知识 / 晒过程 / 聊观点 / 讲故事），每个类型下挂具体结构，共 14 个 |
| **36 计** | 事件怎么拍 | 37 计，每计是一个现成的拍法（事件走向） |

四大脚本下的 14 个结构：

- 教知识：解题型、揭秘型、推荐型、案例型
- 晒过程：火车节、过程展示、任务挑战、测评产品、事件体验
- 聊观点：论证型
- 讲故事：小有成就型、成功案例型、平凡英雄型、苦难经历型

结构清单、知识库出处和代码现状见 `01-脚本结构注册表.md`。

## 二、树的层次与每一跳传什么

树从根往叶走，每一层都要读上一层的结论，而不是重新猜：

```
根：内容规划 → 创作方向        定目的、大类、结构搭配，给出方向卡
中：选题                      把方向卡落成可拍的题，融入爆款元素
叶：脚本 → 分镜 → 标题/开篇/审稿   按结构写成台词和镜头，守住目的
周边：定位、商业定位、内容定位、创作简报、行业建议、起号方案
      成交理由、知识库、对标分析、拆解爆款、跨行业二创、前采提取
```

### 数据契约（每一跳必须携带的字段）

所有板块在衔接时都用同一组字段，不靠自由文字里的标签：

| 字段 | 含义 | 例子 |
|---|---|---|
| `bigType` | 大类 | `四大脚本` / `36计` |
| `kind` | 四大脚本下的类型（36 计为空） | `聊观点` |
| `structure` | 具体结构，写全名 | `聊观点·论证型`、`36计·第32计 换个视角` |
| `purpose` | 目的 | `流量型` / `人设型` / `变现型` |
| `task` | 这一跳要完成的任务，一句话 | `用一个反差让陌生人停下来` |
| `elements` | 爆款元素（八大） | `反差`、`怀旧` |
| `source` | 来源（方向卡或选题的标题） | `方向2：门店试穿过程` |

规则：
- 提示词里按上面的字段写，解析器按同样的字段读，不能只写类型头。
- 跳转时整组字段一起带过去，脚本页的「脚本类型」和「脚本结构」由 `bigType`、`kind`、`structure` 直接设定。
- 认不出的字段要明示（「没认出打法，请手选」），不能静默切到自动决策。

3. ~~「观察型」是否等于「过程展示」~~ 已确认（2026-10-30）：过程展示就是过程展示，原「观察型」改名为「过程展示」，叙事按知识库的进货→成交→技术→售后改写，不保留两个。

## 四、落实顺序

1. 数据契约落到代码（一个共用的模块，提示词、解析器、跳转都从它取字段）。
2. 选题到脚本这一跳先打通，用真实模型验证（已做过一次，需要用契约重做）。
3. 创作方向到选题这一跳，由另一个会话对齐根部。
4. 周边板块逐个按任务书接入。
5. 每跳都有测试：单元测试卡契约，真实模型探针卡输出是否守住结构和目的。
