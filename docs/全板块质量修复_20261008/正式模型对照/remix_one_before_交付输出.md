## 原片火的核心机制分析

原片《点菜先看人数》的核心机制是：**把"应该怎么做"变成一个可视化的操作教学**——用"先……再……"的句式，把抽象的决策（点菜容易点多）变成具体的动作（拿餐具比划桌面），让用户看完立刻能照做。

为什么能跨行业借：
1. **句式结构通用**："先别急着……今天拿……看一眼……再……把……记下来……也得……"——这套句式可以套任何"决策前的检查动作"
2. **解决的是通用痛点**：买之前看不出问题，买完才发现不合适（餐饮是点多了吃不完，家具是买大了门打不开）
3. **呈现方式简单**：一个人、一部手机、拿店里现成的东西做演示，30秒讲完

### 方案1：买家具前，先拿卷尺比门

**一句话**：原片"用餐具演示桌面能摆几盘菜" → 你的"用卷尺演示门框、走道、柜子的真实尺寸关系"

**借了**：开篇句式（"先别急着……今天拿……"）、段落顺序（提醒→演示→记录→原则）、呈现方式（手持道具、现场演示、口播教学）  
**换成自己的**：行业关键词（餐具→卷尺、点菜→买家具、桌面→门框和走道）、演示的事（摆盘子→量尺寸）、痛点（吃不完→门打不开）

#### 迁移对照

| 层 | 原片 | 你的版本 |
|---|---|---|
| **开篇** | "先别急着看招牌" | "买柜子前，先别急着看款式" |
| **道具** | 餐具 | 卷尺 |
| **演示动作** | 拿盘子在桌上摆，看放不放得下 | 拿卷尺量门框、走道，看柜子进不进得去 |
| **记录环节** | "把来几个人、想吃什么记下来" | "把门宽、走道宽、想要的柜子深度记下来" |
| **结尾原则** | "喜欢也得吃得完" | "好看也得搬得进去" |
| **事件/主角** | 餐厅老板教顾客怎么点菜不浪费 | 家具店老板教顾客买之前怎么量尺寸 |

#### 开头（前 3 秒）

**口播**："买柜子前，先别急着看款式。"

**画面**：老板站在展厅里，手里拿着卷尺，身后是一排衣柜样柜（镜头从衣柜摇到老板手上的卷尺）

#### 口播要点

**段1 - 提醒**（对应原片"先别急着看招牌"）  
买柜子前，先别急着看款式。今天拿店里这把卷尺教你：【换成你的：你家哪几个地方必须量】

**段2 - 演示**（对应原片"拿餐具比划桌面"）  
走到一个衣柜前，拿卷尺比划门框位置："看，这个柜子宽X米，你家门框得比它宽至少10公分。"再量走道："从门口到摆柜子的墙，这段走道也得量——柜子得先进门，再转弯。"

**段3 - 记录**（对应原片"把人数和菜记下来"）  
把你家门框宽度、走道宽度、想要的柜子深度，拍个照或记到手机里。

**段4 - 原则**（对应原片"喜欢也得吃得完"）  
柜子再好看，也得搬得进去。

#### 注意

- **原片学不来的**：原片是餐饮场景，顾客天天遇到"点菜"；家具是低频决策，所以开头要更直接点出痛点（"先别急着看款式"后面可以补一句"好多人买回去才发现门打不开"）
- **不是搬运**：
  - 台词：原片讲"盘子和桌面"，你讲"卷尺、门框、走道"——行业关键词全换了
  - 画面：原片拍餐具和餐桌，你拍卷尺、门框位置、衣柜样柜——场景和道具完全不同
  - 事件：原片是"教怎么点菜不浪费"，你是"教买之前怎么量尺寸"——解决的虽然都是"决策失误"，但具体痛点和解决方案完全不同

### 我推荐先拍这个

**推荐方案1**，理由：
1. **最贴档案**：客人最担心的就是"买回去尺寸不合适、挡门"，这条直接解决这个痛点
2. **最好拍**：老板一人、一部手机、一把卷尺（五金店2块钱），展厅里现成的衣柜就能演示，不需要顾客配合、不需要去客户家
3. **流量型目的达成度高**：教"买之前怎么量"是泛知识，覆盖所有要买家具的人（不只是你的客人），评论区会有人问"我家门框XX公分够不够"——天然引互动
4. **可以做成系列**：这条拍衣柜和门框，下一条可以拍"买沙发前，先量客厅进深"，再下一条"买床前，先量卧室长宽和床头柜位置"——沙发、床、衣柜三个品类都覆盖到
