# 跨板块交接审计与开篇钩子修复（2026-10-11）

## 一、开篇钩子：为什么写成局外人口吻、没用好选题的目的和方向

线上记录（2026-10-11 04:49）：选题原文写着「这家地摊老板干了两件事」，开篇输出「这家老板早就想到了」「你看这家老板干了啥」——旁观者口吻，出镜人（师傅）没有开口。

原因（都在组装提示词的环节，不是模型单独的问题）：

1. **没有说话人规则。** 开篇提示词只写了「口吻要和这个号一致」，没有告诉模型开头原话是出镜人自己对着镜头说的，也没有禁止第三人称讲出镜人或这家店。选题原文本身是第三人称写的，模型就照抄框架。
2. **目的和方向埋在长设置块里。** 「内容方向」「视频目的」只是设置块里的几行，排在档案上下文和 36 张卡片之后，没有点名要求开头照它写。
3. **完整目的在有类别时丢失。** `creationSettingsBlock` 只在没有「视频目的」类别时才输出「完整目的」。这条记录的目的是「变现型」，完整的「引流到店、推新品、口碑、涨粉」整段没进提示词。
4. **开篇页切换选题只换了标题。** 选题批次里挑另一条，只调用了 `setTopic`，主线、内容方向、目的还是第 1 条的。

## 四、其他板块的交接审计

已确认的问题（修复见上表）：

1. **整批交接读到第 1 条的标签。** 选题批次「设计开篇」「写成脚本」、方向批次交给选题时，`buildCreationHandoff` 和 `settingsForResult` 会把第 1 条的「视频目的」「内容方向」当成整批的设置。
2. **拆解报告的标签被当成用户的设置。** 拆解报告描述的是别人的原片（视频目的、脚本类型），交给二创时被当成用户的目的。
3. **完整目的丢失。** 所有用 `creationSettingsBlock` 的板块都受影响，不只是开篇。
4. **开篇页切换选题只换标题。**

仍未解决、需要你决定或另行处理：

5. **出镜人没有结构化身份。** 这个档案的人设事实卡（「出镜人是谁」）为空。创作简报里有「我是谁」，但只有读简报人设段的板块能用到它。建议先补全人设事实卡，再决定是否在设置块里加一条「出镜人」。
6. **开头里编的个人经历。** 候选里出现「昨天我在棚外站了两分钟，冻得直哆嗦」这类经历。它标了风险，但没有用假设语气。这需要另外的规则：开头的第一人称经历要么来自素材，要么写成待拍摄确认的假设。
7. **未逐条验证的交接。** 内容规划 → 创作方向、起号方案 → 选题（打法字段）、自由对话 → 各板块，只在代码层面看过，没有实际跑通。
