# 产出质量回归：核实与修复报告

核查对象：本人最近一次“审稿优化”，2026-10-08 03:29左右保存，内容为“凌晨四点的南乐”。核查包含真实原稿、个人要求、保存结果、Dify实际请求与运行记录、当前生产源码、2026-10-07修复前的生产备份，以及本地工作区。

这次不佳有明确的程序和编排原因。部分是近期适配改造引入的回归，部分是此前已经存在、这次同时暴露的问题。没有证据证明只是模型本身变差，也没有把所有问题归咎于最近一次发布。

## 已核实的问题及处理

| 问题 | 本次证据与后果 | 修复 |
|---|---|---|
| 原稿被算成0字 | 原稿为无栏目名的纯文字，生成结果专用解析器识别不到台词，实际请求写成“可识别口播0字、0秒”。这是近期解析改造的回归 | 用户原稿单独解析；纯文字可估算，结构化材料无法分离时报告未知，不伪装成0 |
| 页面时长与预检矛盾 | 页面按403个字符串字符/3估算，口播预检又是0。实际朗读计数为311，按5字/秒约62秒，尚需另留停顿与现场声音 | 页面和预检统一使用朗读计数与5字/秒口径 |
| 勾选要求丢失 | 页面保存中文标签，组装请求时却查编号。真实请求中的结构、文案、情绪要求只剩空项及顿号 | 标签和旧编号都能正确转成审稿要求；保存完整审稿选项供复现 |
| 跨板块旧上下文累积 | 最新审稿沿用自10月4日开始的共用会话，累计14条消息；Dify显示144,077 token | 完整稿件生成不读取旧共用会话；完成后自由对话承接最新成稿，板块追问使用自己的会话 |
| 账号背景覆盖本条内容 | 创作简报要求“产出必须与长期方向一致”，模型反复将本条理解成面向老板、证明编导获客人设 | 简报作为长期背景；当前原稿与本轮明确要求决定本条目的、人群与表达 |
| 手选方法在新分支漏传 | 非广告脚本统一改走适配分支，但该分支未完整接收手选脚本方法、爆款元素、表达重点 | 补齐方法与选择参数，保留自动选择和用户明确选择的区别 |
| 审稿标准相互冲突 | 一边要求按内容形式判断，一边要求命中词表即判不合格、逐词扣分；本次结果还出现105分权重表 | 改为结合原句和语境判断；已有优点可保留，使用唯一100分权重，校对总评与表格 |
| 时长歧义直接造成删场景 | “1-30秒”被直接按30秒理解，环卫、市场被删除，只剩包子铺 | 页面在提交前提示明确30秒以内或1分30秒，未明确时不生成、不扣成功次数 |
| 强制扩充诱发编情节 | “时长不足就补足内容”与“扩充内容”共同推动模型添加原稿没有的物件、数量、动作和购买经历 | 改为深化已有素材、使用真实动作与停顿；缺素材说明补采，不编故事凑秒数 |
| 只加禁止规则仍不稳定 | 独立复测仍生成白萝卜、十二筐、买包子、点头等原稿没有的内容 | 审稿分为编辑与独立事实校对两步；未校对初稿不向用户交付；失败不回退交付初稿、不确认成功次数 |
| 纯文案把报告尾巴算进去 | 纯文案后分隔线没有结束口播提取，后面的总评说明被计入时长 | 补齐分隔线边界和“纯文案”标题兼容；交付统计按实际纯文案计算 |
