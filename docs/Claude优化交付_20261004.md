### 3.1 连续创作（阶段 1）
- `lib/creation-session.ts`：新增 `openCreation` / `openCreationSafely`——保存完整创作需求后再跳；保存失败不跳、原页内容不动；**同一份内容重试沿用同一个请求编号**（服务端 `save_creation_session` 按编号幂等，不会多建作品），成功后下次才换编号；只有脚本正文/拆解报告的补成 `sourceContent`。
- `components/workspace/CreationLinks.tsx` 改用它；选题、脚本、审稿、分镜、开篇/起号、拆解页里所有直接 `putHandoff` 的按钮全部换成 `buildCreationHandoff(...) + openCreationSafely`，目的/人群/结构/源资料跟着走（原来这些按钮只带正文，设置全丢）。
  - 说明：这些页面的 `nextActions` 在 ResultPanel 里其实只在不支持「继续创作」的板块显示，主入口是 CreationLinks；按钮也一并改了，避免以后打开时又是旧逻辑。
- `lib/creation-snapshot.ts`：白名单补 `topicTactics`。
- `lib/creation-restore.ts` + `CreationRestoreGate`：同一标签页刷新、或作品在该板块跳转后已生成新版本 → 不再填快照，交给作品恢复（最新稿 + 作品需求）；第一次打开 / 换设备且还没生成过 → 填快照。`GET /api/creation-sessions` 多回 `created_at`。
- `lib/creation-work-resume.ts`：先铺 `works.creation_brief`（设置、锁定原文、最初源资料），再叠每版生成的设置；还没生成过时用作品需求里带来的内容（不再只剩标题）。
- 结果画布：`components/workspace/ResultPanel.tsx` 加「在画布里改」，用 Codex 的 `ResultCanvas`（右侧抽屉，手机全屏）。保存版本走新接口 `POST /api/result-versions`（`lib/result-versions.ts`）：一条生成结果第一次保存时新建一条同板块的「画布改稿」历史记录（`input_data.canvasOf`、`canvasVersions` 存全部版本），之后更新同一条，`result` 永远是最新一版——作品恢复、拍摄交付包、全部产出不用改就拿到最新采用稿。只能更新本人带 canvasOf 标记的记录；作品要是本人的且档案对得上。后台监控的生成统计排除改稿记录（`app/api/admin/monitor/route.ts` 三处）。显示、复制、继续创作、禁忌扫描都用最新一版。
- 二创：`flowContext` 补 `originContent`（最初带进来的 / 本次原片原文），选一个方案带走时源资料不被单个方案顶替。
- 作品：`GET /api/works` 支持 `?offset=`、`?group=`（active/toShoot/shot/published，与 `progressGroup` 同口径）、`?counts=1`；作品环节按页取完（一条作品版本多时不再被 1000 行上限截断，算成「没做」）。创作进度页按组服务端筛、翻页，`?group=toShoot` 可直达；作品卡片「拍摄交付包」点开时现取完整作品（`fetchWork`，含 creation_brief）。拍摄标记仍只存本机，组件里写明。

4. 线上实测记录 `docs/联网改造六附件实测_20261002.json`：六种附件上传成功、「六附件读取且不联网」分支和回答正确，与最新 DSL 一致。

## 6. HTTPS

核实结果：服务器 nginx 是 `server_name _`（没有域名），网站走 http + IP。浏览器把它当非安全环境，所以剪贴板接口、麦克风都用不了（剪贴板已有兼容方案，语音录入因此没做）。
要上 HTTPS 需要：一个域名 → 国内服务器还需 ICP 备案 → 解析到服务器 → 申请证书（腾讯云免费证书或 Let's Encrypt，自动续期）→ nginx 配 443 和 80 跳转。你之前说域名先不做，所以**这次没有动**，也没有用自签证书（浏览器照样报不安全，等于没做）。

## 8. 阶段 4：专业 / 团队能力（只评估，没建入口）

先看了现有数据模型：没有团队 / 成员 / 角色表，所有内容按 `user_id` 归属，行级权限都是「只本人」。所以多人协作、权限、操作记录都要新建结构，不能做"假入口"。

| 能力 | 现有基础 | 建议实现 | 迁移 | 成本边界 |
|---|---|---|---|---|
| 周计划 / 批量任务 | 7 天起号计划、待办、作品分组 | 「本周要拍」= 从选题库挑 N 条建作品 + 排到哪天；批量生成走现有配额预占，一条一扣 | `works` 加 `planned_for date` | 批量生成按条计次，不能一次绕过额度 |
| 品牌规范 | 人设事实卡、禁忌、风格预设 | 已基本覆盖：事实卡管事实、禁忌管不能说的、风格预设管写法；缺"统一的口播禁用词/必带话术"可放进风格预设 | 无 | 低 |
| 审核意见 | 审稿板块 | 作品上挂「意见」（谁、对哪一版、哪一段、是否已处理），依赖版本记录（画布改稿已具备） | 新表 `work_comments` | 中 |
| 多人协作 / 权限 | 无 | 团队表 + 成员角色（拥有者/编辑/只读）+ 共享档案；所有内容表的行级权限从「本人」扩到「本人或同团队」 | `teams`、`team_members`，改约 15 张表的 RLS | **高**：RLS 全面改写风险最大，必须先在隔离库演练 |
| 操作记录 | admin_logs（只管理员） | 用户侧操作日志（谁改了档案、删了素材、采用了哪个预设） | 新表 `activity_logs` | 中 |
| 外部视频 / 剪辑 / 自动发布 | 无 | 需要平台开放接口和授权（抖音开放平台等），**条件不具备**，只记录依赖 | — | 等接口 |

建议顺序：周计划 → 审核意见 → 操作记录 → 团队与权限（最后做，先演练 RLS）。
