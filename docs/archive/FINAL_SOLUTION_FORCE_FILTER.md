# ✅ 最终解决方案：强制过滤"内容方向与配比"

## 🎯 问题回顾

经过多次尝试，发现之前的过滤方法都无法完全阻止"内容方向与配比"出现在提示词中。

### 尝试过的方法（都失败了）

1. ❌ 在extractRelevantPositioningInfo函数中添加黑名单关键词
2. ❌ 移除白名单中的"内容方向"关键词
3. ❌ 优化章节标题检查逻辑（黑名单优先）
4. ❌ 在选择定位时使用过滤内容
5. ❌ 在生成提示词时二次过滤

### 为什么都失败了？

**根本原因：**
- extractRelevantPositioningInfo函数的逻辑太复杂
- 白名单和黑名单存在冲突
- 章节内容跨多行，行级过滤无法完全清除段落
- 过滤发生在数据填充时，而不是最终发送时

---

## ✅ 最终解决方案（根治）

### 核心思路：最终防线

**不再依赖复杂的过滤逻辑，而是在发送给Dify之前，添加一道最终防线，强制移除所有相关内容。**

### 实现位置

在handleGenerate函数中，**在发送fetch请求之前**，对完整的query进行最终过滤。

### 完整代码

\\\javascript
// 🔥 最终过滤：强制移除"内容方向与配比"及相关段落
const removeKeywords = [
  '## 💎 内容方向与配比',
  '### 当前阶段推荐配比',
  '### 流量型内容',
  '### 变现型内容', 
  '### 人设型内容',
  '**拍摄方向思路**',
  '**目的**：快速涨粉',
  '**目的**：引导本地用户',
  '**目的**：让用户记住你',
  '**必须体现的成交理由**',
  '**转化路径**：视频最后'
];

let filteredQuery = '';
let skipSection = false;
const queryLines = query.split('\n');

for (let i = 0; i < queryLines.length; i++) {
  const line = queryLines[i];
  
  // 检查是否命中移除关键词
  const shouldRemove = removeKeywords.some(kw => line.includes(kw));
  
  if (shouldRemove) {
    skipSection = true;
    continue;
  }
  
  // 遇到新的##或###标题，且不在移除列表中，结束跳过
  if ((line.startsWith('##') || line.startsWith('###')) && skipSection) {
    if (!removeKeywords.some(kw => line.includes(kw))) {
      skipSection = false;
    }
  }
  
  // 如果不在跳过状态，保留这一行
  if (!skipSection) {
    filteredQuery += line + '\\n';
  }
}

query = filteredQuery;

// 然后发送请求
const response = await fetch("/api/dify/stream", {
  method: "POST",
  headers: { "Content-Type": "application/json" },
  body: JSON.stringify({
    query: query,
    ...
  })
});
\\\

## 🎯 工作原理

### 第1步：定义移除关键词列表
包含所有需要移除的章节标题和段落标识：
- 章节标题：## 💎 内容方向与配比
- 子章节：### 流量型内容、### 变现型内容等
- 段落标识：**拍摄方向思路**、**目的**：快速涨粉等

### 第2步：逐行扫描
遍历query的每一行，检查是否包含移除关键词。

### 第3步：段落级跳过
- 当遇到移除关键词时，skipSection = true
- 继续跳过后续行，直到遇到新的章节标题（##或###）
- 新章节标题不在移除列表中时，skipSection = false

### 第4步：重新组装
只保留未被跳过的行，重新组装成ilteredQuery。

### 第5步：替换原query
将过滤后的ilteredQuery赋值给query，然后发送给Dify。

## ✅ 为什么这个方案是根治方案？

### 1. 最终防线
- 不依赖前面的复杂逻辑
- 无论前面如何处理，最终都会被这一层过滤
- 即使extractRelevantPositioningInfo失效，也能保证结果正确

### 2. 段落级清除
- 不是行级过滤，而是段落级
- 遇到章节标题时进入跳过模式
- 直到遇到新的有效章节才结束跳过
- 确保整个段落被完整移除

### 3. 精确匹配
- 使用完整的章节标题字符串
- 避免误触发（不会因为"内容方向"而误删其他内容）
- 可以精确控制要移除的内容

### 4. 易于维护
- 只需要在emoveKeywords数组中添加/删除关键词
- 不需要修改复杂的过滤逻辑
- 新增需要屏蔽的内容时，只需添加一行
